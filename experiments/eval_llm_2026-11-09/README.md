# Jev 입력으로 GPT · Claude 모델 비교 (2026-11-09~10)

앞선 Jev 실험(2026-11-04~05)에서 Jev가 받은 창(판단을 한 번 하는 시간 구간)별 입력을 GPT 모델 3개와 Claude 모델 2개에 그대로 주고, 판단 결과와 응답 시간을 규칙표 · Jev와 비교한 실험입니다. 입력은 규칙표가 선별한 후보 가운데 고르는 E5_C0와 지원 6개 전체에서 고르는 E5_J 두 가지입니다. 두 입력 모두 규칙표(F1 0.748)보다 F1이 높은 줄은 없었고, GPT · Claude 모델의 답만 쓴 줄에서 가장 높은 F1은 E5_C0의 gpt-4o-mini 0.737, E5_J의 gpt-6.1-sol 0.696입니다. 응답 시간 중앙값은 Jev 194.4 ms(E5_C0)와 196.2 ms(E5_J), GPT · Claude 모델 884.5~2,092.9 ms, 규칙표 0.0047 ms입니다. AI 담당의 시나리오 세트 3개에도 모델 4개를 더 돌렸습니다(아래 '시나리오 세트').

## 시나리오 세트

AI 담당의 결과 표에 있는 모델 모두가 세 세트에서 값을 갖도록 모델 4개를 더 돌렸습니다. 세트는 novel(SUM 형식, 60건: 도움 28, 대기 32), heldout1(56건: 도움 28, 대기 28), heldout2(56건: 도움 32, 대기 24)입니다. 프롬프트는 AI 담당의 파일을 데이터로 읽어 그대로 재현했고, 그 코드는 실행하지 않았습니다. 선택지는 지원 9개 + none이고, 세트와 모델마다 3번 돌렸습니다.

- 점수(균형 정확도, BA) = (도움 사례 가운데 고른 지원이 허용 목록에 든 비율 + 대기 사례 가운데 답이 null이 아니고 화면에 보이는 지원 7개도 아닌 비율) / 2. AI 담당 실험의 정의를 따랐습니다.
- 같은 답에서 정밀도 · 재현율 · F1과 Macro-F1을 내는 도구는 `tools/score_scen_f1.py`와 `tools/score_scen_f1_macro.py`입니다. 아래 표는 AI 담당 실험의 값과 나란히 볼 수 있게 균형 정확도로 적었습니다.
- 1초 변형: 답이 null이거나 1,000 ms보다 늦은 사례는 AI 담당의 규칙표 답으로 바꿉니다.

# 사례 창 목록과 Jev 기준 답의 제한본(호출 없음)
python "$P\tools\cell_windows.py" $K E5_J "$P\stage2_prep"

python "$P\tools\run_gpt.py" --kit $K --arm E5_J --windows "$P\stage2_prep\E5_J_cell_windows.txt" --model gpt-4o-mini-2024-07-18 --env backend\.env --cache "$P\cache" --out "$P\runs\gpt-4o-mini-2024-07-18_E5_J_cells"

python "$P\tools\one_second.py" $P $K "<앞선 Jev 실험의 기록 실행 폴더>"
python score.py --data data/E5_J.jsonl --answers <runs 폴더>\gpt-4o-mini-2024-07-18_E5_J_cells\answers.jsonl
# 규칙표 응답 시간: 작업 폴더 위치를 KIOSK_WORKSPACE로 줌, 앞선 Jev 실험의 backend 가상환경(Python 3.12)
$env:KIOSK_WORKSPACE = "<비전 담당 작업 폴더>"
python "$P\tools\time_rule_table.py" "<PR #77 커밋 3c936ae의 backend 폴더>" "$P\stage2_prep\E5_J_cell_windows.txt" "$P\runs\rule_table_timing\timing.json"
# 시나리오 세트(세트 3개 × 모델 × 실행 1~3)

`run_gpt.py` 명령에 `--print-example`을 더하면 첫 창의 프롬프트를 출력합니다.

## 파일

| 파일 | 내용 |
|---|---|
| `tools/run_gpt.py` | GPT 실행기(`--windows`로 물을 창을 제한) |
| `tools/run_claude.py` | Claude 실행기. 프롬프트와 출력 파일 형식은 `run_gpt.py`와 같음 |
| `tools/run_gemini.py` | Gemini 실행기(REST, responseSchema enum, temperature 0). HTTP 403에서 더 가지 못함 |
| `tools/cell_windows.py` | 사례 창 목록과 Jev 기준 답의 제한본(제한해도 Jev 줄이 같은지 확인용) |
| `tools/predict_cost.py` | E5_C0 실행의 토큰 사용량으로 E5_J 실행의 비용을 예측 |
| `tools/one_second.py` | 1초 변형 답 파일(GPT, Claude, Jev) |
| `tools/time_rule_table.py` | 규칙표 자체의 응답 시간 |
| `tools/scen_prep.py`, `tools/run_scenarios.py` | 시나리오 세트 입력 만들기와 실행 |
| `tools/score_scen.py`, `tools/score_scen_1s.py` | 시나리오 세트의 균형 정확도와 1초 변형 |
| `tools/score_scen_f1.py`, `tools/score_scen_f1_macro.py` | 시나리오 세트의 정밀도 · 재현율 · F1, 대기 F1과 Macro-F1(저장된 답만 씀, 호출 없음) |

아래 실행 기록과 모델 답 캐시는 저장소에 넣지 않았고 비전 담당 작업 폴더에 있습니다.

## 한계

- 서로 다른 프롬프트마다 첫 유효 답 하나만 썼고, 같은 프롬프트는 그 답을 다시 썼습니다. 기본 temperature로 돈 모델(gpt-6.1-sol, Claude 두 모델)도 표본은 하나이고, 어느 모델도 답의 흔들림은 재지 않았습니다.
- E5_J는 사례 창 1,589개만 물었습니다. 채점한 줄은 바뀌지 않지만(Jev로 확인), 창 3,148개 전체의 답 분포는 GPT · Claude에 없습니다.
- 응답 시간은 실험한 PC에서 동시 요청 2개로 잰 값이고 API까지의 네트워크 시간이 들어 있습니다. Jev는 같은 조건이지만 다른 날(2026-11-04~05)에 쟀고, 시간대도 다릅니다.
- 1초 변형은 규칙표 결정으로 돌아가므로, 느린 모델일수록 1초 줄이 규칙표 줄에 가까워집니다(gpt-6.1-sol은 규칙표 줄과 같음).
- 시스템 메시지의 답 형식 줄은 이 실험이 더한 것입니다. Jev는 시스템 문장 없이 질문을 API의 필드로 받습니다.
- Claude 두 모델은 thinking을 껐고, gpt-6.1-sol은 기본 추론으로 돌았습니다. 라벨 v5는 잠정이고, 평가 사례는 137건, C4의 대기 사례는 9건입니다.
- 시나리오 세트: 이 실행은 동시 요청 2개(2026-11-10), AI 담당의 실행은 동시 요청 4개로 다른 시각에 돌아 응답 시간 조건이 다릅니다. OpenAI가 일부 실행에서 입력 캐시(1,024토큰이 넘는 프롬프트)를 적용해 GPT 실행마다 비용이 다릅니다.
