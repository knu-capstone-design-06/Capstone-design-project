# 상황 태그가 있는 입력(값 묶음 b0_rA)으로 다시 돌린 모델 비교 (2026-11-12)

논문 원고(2026-11-12)의 표 4에 있는 두 조건, 후보 내(E5_C0)와 후보 제한 없음(E5_J)의 창(판단을 한 번 하는 시간 구간)별 입력을 값 묶음 b0_rA로 다시 만들고, `eval_llm_2026-11-09`와 같은 모델 5개를 이 입력으로 다시 돌린 확인 실험입니다. `eval_llm_2026-11-09`는 상황 태그가 붙은 창이 없는 값 묶음 b0_r0를 썼고, b0_rA에서는 E5_J의 사례 창(평가 사례 137건에 속한 창) 1,589개 가운데 21개에 태그가 붙습니다. b0_rA에서 규칙표는 TP 52, FP 5, FN 15, TN 65(도움 F1 0.839, Macro-F1 0.853)이고, Jev는 후보 내에서 Macro-F1 0.845, 후보 제한 없음에서 0.473입니다. 논문 표 4는 상황 태그 없는 입력(b0_r0)의 결과를 쓰고, 이 폴더의 결과는 논문에 쓰지 않았습니다. b0_rA에서도 논문 3.4절의 두 진술과 같은 결과가 나왔습니다. 후보 내에서 gpt-6.1-sol, claude-haiku-5-5, claude-sonnet-5-5의 도움 F1은 0.455, 0.414, 0.414로 낮았고, 후보 제한을 없애면 Jev, gpt-4o-mini, gpt-5.4-mini의 대기 F1이 0.861 → 0.346, 0.861 → 0.321, 0.760 → 0.333으로 낮아졌습니다.

## 비교한 조건

| 이름 | 뜻 |
|---|---|
| 값 묶음 | 상황 태그 규칙의 기준값 파일 |
| b0_r0 | `eval_llm_2026-11-09`가 쓴 값 묶음. 상황 태그가 붙은 창이 없음 |
| b0_rA | 역할 경계값(다른 머리를 동행자와 뒤 사람으로 가르는 값: 상대 거리 1.5, 옆 거리 0.5)을 쓴 값 묶음. 논문 표 3이 쓰는 묶음 |
| E5_C0(후보 내) | 규칙표가 선별한 후보 + none 가운데 고름. b0_rA에서 측정 가능하고 후보가 있는 창 191개, 그 가운데 사례 창 102개 |
| E5_J(후보 제한 없음) | 지원 6개 + none 가운데 고름. 측정 가능한 창 3,148개 가운데 사례 창 1,589개만 물음 |
| 규칙 기반 판단 | 규칙표 자신의 b0_rA 결정 |
| Jev | 2026-11-05 b0_rA 실행에서 기록한 `jev-1.13.0` 답(새 호출 없음) |

- 평가 사례는 장면과 터치 조건의 조합 137건(도움 사례 67건, 대기 사례 70건)이고, 라벨 v5(허용 행동을 규정한 잠정 라벨)가 사례마다 정답을 정합니다.
- 입력은 앞선 Jev 실험(2026-11-04~05)의 실행기(규칙표는 PR #77, 커밋 `3c936ae`)를 b0_rA 값을 써서 캐시 모드로 다시 돌려 만들었습니다. API 호출과 캐시 누락은 0번이고, 저장된 2026-11-05 b0_rA 실행과 같은 입력이 나왔습니다. b0_r0로 같은 경로를 돌리면 평가 키트의 파일과 바이트 단위로 같습니다.
- 모델 실행은 `eval_llm_2026-11-09`의 실행기(`run_gpt.py`, `run_claude.py`)를 고치지 않고 같은 설정(동시 요청 2개, 시간 제한 30초, 최대 출력 토큰 256)으로 썼습니다. b0_r0 실행의 캐시에 없는 프롬프트만 새로 물었습니다. 새 프롬프트는 모델마다 E5_C0 46개, E5_J 사례 창 86개이고, 2026-11-12에 새로 받은 답은 모두 660개입니다.
- E5_C0를 모든 창(191개)에 묻든 사례 창(102개)에만 묻든 표 4의 값은 같습니다(Jev로 확인).

## 실행

창별 입력과 라벨, 평가 키트의 `score.py`, 앞선 Jev 실험의 기록 실행은 저장소에 없고 비전 담당 작업 폴더에 있습니다. `--kit`에는 창별 입력과 라벨이 든 폴더를 줍니다. GPT 실행기는 `--env`로 준 파일(`backend/.env`)의 `OPENAI_API_KEY`를, Claude 실행기는 `--env`로 준 파일의 `ANTHROPIC_API_KEY`를 읽습니다.

도구는 비전 담당 작업 폴더의 배치를 기준으로 경로를 잡습니다. 그래서 저장소 안에서 바로 실행되지는 않고, 아래 명령은 실험 때 돌린 순서를 보여 줍니다.

```powershell
$RA = "experiments\eval_llm_2026-11-12_rA"
$T  = "experiments\eval_llm_2026-11-09\tools"
# 입력 다시 만들기(호출 없음)
python "$RA\tools\build_inputs.py" --run-j "<앞선 Jev 실험의 b0_rA 실행 폴더>" --run-c0 "<같은 폴더>" --out "<출력 폴더>"
python "$RA\tools\kit_rA.py" run "$T\cell_windows.py" $RA E5_J "$RA\prep"
# 규칙표 줄 확인과 새 호출 수 세기(호출 없음, 키를 읽지 않음)
python "$RA\tools\kit_rA.py" score --rule-table
python "$RA\tools\count_calls.py" --cache "<실행기 캐시 폴더>"
# 모델마다 두 입력(GPT는 run_gpt.py, Claude는 run_claude.py)
python "$T\run_gpt.py" --kit $RA --arm E5_C0 --model gpt-4o-mini-2024-07-18 --env backend\.env --cache "$RA\cache" --out "$RA\runs\gpt-4o-mini-2024-07-18_E5_C0"
python "$T\run_gpt.py" --kit $RA --arm E5_J --windows "$RA\prep\E5_J_cell_windows.txt" --model gpt-4o-mini-2024-07-18 --env backend\.env --cache "$RA\cache" --out "$RA\runs\gpt-4o-mini-2024-07-18_E5_J_cells"
python "$T\run_claude.py" --kit $RA --arm E5_C0 --model claude-haiku-5-5 --env <ANTHROPIC_API_KEY가 든 env 파일> --cache "$RA\cache" --out "$RA\runs\claude-haiku-5-5_E5_C0"
# 표 4 형식의 결과(호출 없음)
python "$RA\tools\table4_rA.py" --json-out "$RA\runs\table4_rA.json"
```

- b0_rA 답은 `tools/kit_rA.py`나 `tools/table4_rA.py`로 채점합니다. 평가 키트의 `score.py`를 그대로 쓰면 키트의 b0_r0 `window_cells.csv`를 읽어, 답하지 않은 창이 b0_r0 규칙표 결정으로 채워집니다.
- 한 모델의 전체 열: `python tools/kit_rA.py score --data data/E5_J.jsonl --answers runs/<모델>_E5_J_cells/answers.jsonl --name <모델>`.
- `build_kit_2026-11-08.py`는 작업 폴더 위치를 환경 변수 `KIOSK_WORKSPACE`로 받습니다.
