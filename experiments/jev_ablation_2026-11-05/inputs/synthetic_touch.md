# 합성 터치 조건 (입력 설명)

`inputs/aligned/`와 `inputs/aligned_touch_none/`의 터치 칸은 실제 터치 기록이 아니고 합성 터치 로그입니다. 10-28 팀 촬영 35개에는 내보낸 터치 기록이 없어서, E3가 합성 세션 7개를 고정해 모든 영상의 같은 카메라 창에 하나씩 넣었습니다.

- 출처: FrontAI 합성 터치 로그 v3(2026-10-29 생성, seed 20261029, 시나리오 44개 × 사례 5개, 세션 225개). 인계 문서 원문: "이 데이터는 터치 로그 수집·집계 및 연계 코드를 점검하기 위한 합성 데이터입니다. 실제 사용자 행동, 불편 상태, 성능 평가 결과 또는 팀이 확정한 판단 기준이 아닙니다."
- 조건 고르기: 터치는 영상의 장면이나 기대 태그로 고르지 않았습니다. 조건 7개를 2026-11-04에 먼저 고정하고, 같은 터치 순서를 모든 비교 줄에 그대로 씁니다(작성자 작업 공간 `4_vision/eval_ab_2026-11-04/tools/conditions.py`).
- 배치: 합성 세션의 첫 사건부터 마지막 사건까지를 영상의 차례 [시작, 끝]에 선형으로 맞춥니다(`fit`). 속도 프로필은 생성기의 기준인 medium(timeMultiplier 1.0)입니다. 이 패키지의 입력은 모두 이 배치(`fit-medium`)입니다. 차례가 둘인 영상은 둘째 차례의 세션 id에 `#t2`를 붙여 새 세션으로 둡니다.

## 조건 7개

생성 의도와 조건인 까닭은 `conditions.py`의 원문입니다.

| 조건 | 시나리오 | 이름 | 생성 의도 | 조건인 까닭 |
|---|---|---|---|---|
| C0 | 49(둘째 세션) | no_touch | 49 둘째 세션: session_start와 menu 화면 진입만 있음(누름 0) | 로그는 관측 중이나 누름이 없음(창 안 터치 없음 = 참) |
| C1 | 1 | steady | 1: 익숙한 사용자의 빠른 정상 주문과 모의 주문 완료 | 빗나감 · 되돌아감 없이 꾸준히 눌러 주문을 마침 |
| C2 | 8 | miss_fix | 8: 메뉴와 주문 확인에서 같은 화면 도움 버튼 근처 빗나감마다 바로 해당 버튼을 누름 | 빗나감 뒤 바로 고침의 반복(트리 표 3-가 4-1의 여는 신호) |
| C3 | 22 | backs | 22: 장바구니가 변하지 않는 주문 확인과 메뉴 사이 반복 이동 | 되돌아감(review → menu) 1번 이상(트리 표 3-가 4-2의 여는 신호) |
| C4 | 51 | long_pause | 51: 짧은 무입력 뒤 같은 주문을 계속하고 기존 장바구니를 유지 | 누른 뒤 긴 무입력(흐름의 대부분) 뒤 이어서 진행 |
| C5 | 17 | misses_no_fix | 17: 여러 영역에서 산발적으로 빠르게 누르고 정정 흐름은 없음 | 버튼 밖 누름만 있고 바로 고침이 없음; 조용한 혼자 사용자 장면과 겹치면 모순 칸 |
| C6 | 없음 | missing | 터치 기록 없음(열 결측) | 입력 결측: 창 안 터치 여부를 알 수 없음 |

C0~C5는 `inputs/aligned/<영상>.jsonl.gz`에, C6(터치 칸이 모두 비어 있음)은 `inputs/aligned_touch_none/<영상>.jsonl.gz`에 있습니다.

## 모순 칸

장면의 계획 행동과 맞지 않는 터치 조건의 칸은 정책 점수에서 뺍니다(판단 라벨의 `eff_class`가 `contradictory`).

- 누르지 않는 장면(S4 '누르지 않는 시간', S2a '상의할 때는 누르지 않음', S3 '휴대폰을 20초 봄') × 누름이 차례 전체에 퍼진 조건(C1 · C2 · C3 · C5)
- 조용한 혼자 사용자 장면(S0 · Q2 · Q3 · card) × C5

모순 칸(881창)을 빼서 값 묶음 `b0_r0`의 합성 터치 창 3,892개 가운데 점수 대상은 3,011개입니다.

## 실행기가 읽는 칸

창 기록의 `touch.taps_segment`, `misses_recent`, `fixes_recent`, `backs_recent`, `pause_s`, `options_open`, `screen`, `steps_left`, `progress_segment`를 PR #77 `WindowInput`의 같은 이름 칸에 넣습니다(`tools/run_jev_ablation.py` `load_aligned`). 상황 태그 · 시선 · 측정 가능 여부 · 세션 전환은 같은 창의 E3 AB0 줄(`inputs/e3_windows/windows_<값 묶음>.csv.gz`)에서 가져옵니다. 태그 이름만 있으므로 Jev state의 `situation.evidence`는 비어 있습니다.
