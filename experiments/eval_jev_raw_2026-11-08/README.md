# Jev에 카메라 숫자를 직접 주는 실험 (2026-11-08)

규칙이 만든 상황 태그 대신 MediaPipe와 H1 머리 탐지기에서 가공한 숫자를 터치 값과 함께 Jev(`jev-1.13.0`)에 주고, 지원 6개와 none 가운데 하나를 고르게 한 실험입니다. 이미지는 보내지 않았고 숫자와 이름, 질문 문장만 보냈습니다. 바로 고르는 RAW-1은 상황 태그를 받아 후보 제한 없이 고르는 조건(J)과 거의 같았습니다(TP 48, FP 51; J는 49, 52). 상태 점수 5개를 먼저 내고 고르는 RAW-2는 도움을 가장 많이 냈지만(TP 58/67, 지정 지원 재현율 0.776) 대기 사례(기다려야 하는 평가 사례) 70건 가운데 55건에서 개입했고, J · RAW-1 · RAW-2의 정확도 · 정밀도 · F1은 모두 규칙표(0.788, 0.896, 0.748)보다 낮습니다.

## 비교한 조건

창(판단을 한 번 하는 시간 구간), 규칙표 흐름, 채점은 앞선 Jev 실험(2026-11-04~05)의 조건 J와 같고, 요청의 관측 부분만 바꿨습니다.

| 결과 표의 줄 | 뜻 |
|---|---|
| 규칙표 | PR #77(커밋 `3c936ae`)의 규칙표가 직접 고름 |
| Jev: 점수 뒤 고르기(C) | 앞선 Jev 실험의 조건 C. 상태 점수를 먼저 내고, 규칙표가 선별한 후보 + none 가운데 고름 |
| Jev: 후보 제한 없이 고르기(J) | 앞선 Jev 실험의 조건 J. 규칙이 만든 상황 태그와 시선, 터치 값을 받아 지원 6개 + none 가운데 고름 |
| RAW-1 | J의 상황 태그와 시선 대신 카메라 숫자를 받아, 지원 6개 + none 가운데 바로 고름 |
| RAW-2 | RAW-1과 같은 입력으로 1단계에서 상태 점수 5개(터치 어려움, 헤맴, 시각 어려움, 망설임, normal)를 내고, 2단계에서 그 점수를 함께 받아 지원 6개 + none 가운데 고름 |

- 영상과 창: 2026-10-28 팀 촬영 영상 35개에 합성 터치 조건 7개(C0~C6, 녹화에 더한 터치 패턴)를 붙여 창 3,892개를 만들었고, 측정 가능한 창 3,344개만 물었습니다(J와 같음). 영상 20261028_165108(1배 줌으로 찍혀 모든 평가에서 뺀 영상)은 J처럼 채점에서 뺐습니다.
- 카메라 숫자(`state.camera`): 창 끝 t 직전 3초(t − 3초 < 프레임 시각 ≤ t)의 프레임에서 값마다 최솟값 · 중앙값 · 최댓값을 냅니다. 출처는 비전 재생 기록(초당 약 10장)이고, 3초는 값 묶음 `b0_r0`(상황 태그 규칙의 기준값 파일)의 상황 창 길이([파일럿] 값)입니다.
- 보내지 않은 것: 이미지, 상황 태그, 시선, 규칙표의 후보 선별과 자체 질문, P1 카메라 시점, 역할 판정 값(`people_behind_count` · `companion_box`). 화면 · 터치 · 세션 값과 선택지는 J와 같습니다.
- 그림자 모드: Jev의 선택은 뒤 창의 상태를 바꾸지 않습니다. Jev가 고른 지원은 규칙표가 같은 지원을 유지하는 동안 화면에 남고, 아니면 한 창만 보인다고 가정했습니다(앞선 Jev 실험과 같음).

| 카메라 숫자 묶음 | 값 |
|---|---|
| 얼굴 | 보인 비율, yaw · pitch · roll(도), 시작 자세 대비 yaw · pitch 변화, 두 눈 사이 거리 ÷ 화면 폭, 얼굴 중심 |
| 몸 | 보인 비율, 어깨 두 점의 visibility 평균, 어깨 가운데 |
| 머리 | H1이 찾은 머리 수, 주 사용자 머리가 보인 비율, 다른 머리마다 보인 비율, 상대 거리(`rel_dist`), 옆 거리(`lateral`)와 세로 거리(`vertical`) |

값 정의 24줄(영어)은 질문마다 `instructions.camera_fields`로 넣었습니다(`tools/camera_features.py`의 `FIELD_DEFS`).

## 결과 (라벨 v5, 도움 사례 67건과 대기 사례 70건)

평가 사례는 장면과 터치 조건의 조합이고, 라벨 v5(허용 행동을 규정한 잠정 라벨)가 사례마다 정답을 정합니다. 도움 사례는 도움이 필요한 사례, 대기 사례는 기다려야 하는 사례입니다.

| 조건 | TP | FP | FN | TN | 정확도 | 정밀도 | 재현율 | F1 | 지정 지원 재현율 | C4 거짓 경보 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 규칙표 | 43 | 5 | 24 | 65 | 0.788 | 0.896 | 0.642 | 0.748 | 0.582 | 3/9 |
| Jev: 점수 뒤 고르기(C) | 42 | 5 | 25 | 65 | 0.781 | 0.894 | 0.627 | 0.737 | 0.567 | 3/9 |
| Jev: 후보 제한 없이 고르기(J) | 49 | 52 | 18 | 18 | 0.489 | 0.485 | 0.731 | 0.583 | 0.612 | 9/9 |
| RAW-1: 카메라 숫자 + 터치에서 바로 고르기 | 48 | 51 | 19 | 19 | 0.489 | 0.485 | 0.716 | 0.578 | 0.567 | 9/9 |
| RAW-2: 카메라 숫자 + 터치에서 점수 뒤 고르기 | 58 | 55 | 9 | 15 | 0.533 | 0.513 | 0.866 | 0.644 | 0.776 | 9/9 |

- TP = 도움 사례에서 시작 시각 이후 허용된 형태의 개입이 보임, FP = 대기 사례에서 개입이 보임. 정확도 = (TP + TN) / 137, 정밀도 = TP / (TP + FP), 재현율 = TP / 67, F1 = 2TP / (2TP + FP + FN), 지정 지원 재현율 = 그 사례의 지정 지원 자체가 보인 사례 / 67(논문의 적합 기능 제공률).
- C4 거짓 경보: 긴 무입력 조건(C4)의 대기 사례 9건 가운데 개입한 사례의 수.
- 앞 세 줄은 앞선 Jev 실험의 기록 실행을 이 폴더의 채점기로 다시 채점한 값이고, TP부터 지정 지원 재현율까지 논문용 결과표의 줄과 같습니다. Jev 줄의 C4 값은 이 실험에서 처음 냈습니다.

주요 관찰:

1. RAW-1은 J와 거의 같았습니다. TP는 48과 49, FP는 51과 52, F1은 0.578과 0.583, 지정 지원 재현율은 0.567(38/67)과 0.612(41/67)입니다. 두 조건이 모두 답한 창 3,148개 가운데 같은 지원을 고른 창은 2,321개입니다. J가 받은 상황 태그는 none이나 unknown(null)뿐이었습니다(J의 창 3,682개 가운데 none 2,954, unknown 728).
2. RAW-2가 더 도운 곳은 지정 지원을 터치 조건이 정한 사례 48건입니다(C2의 `large_button`, C3의 `highlight_next_action`). 이 사례의 TP는 RAW-2 42, J 33, RAW-1 32, 규칙표 35입니다. 카메라 장면이 지정 지원을 정한 사례 19건에서는 Jev 세 조건 모두 TP 16입니다(규칙표 8).
3. C4의 대기 사례 9건에서 J, RAW-1, RAW-2는 모두 개입했습니다. 규칙표와 점수 뒤 고르기는 3/9입니다.
4. 창 단위의 허용 비율은 세 조건 모두 무작위로 고를 때와 비슷합니다. 채점 대상 창 2,710개 가운데 답한 창 2,286개에서 허용된 선택은 J 1,423개, RAW-1 1,451개, RAW-2 1,448개이고, 선택지 7개를 고르게 고를 때의 기대 비율은 0.635(약 1,452개)입니다.
5. RAW-2의 1단계 상태 점수는 앞선 Jev 실험의 조건 B(상황 태그 + 시선 + 터치)와 같은 창 1,027개에서 다섯 질문 모두 AUROC가 높았습니다. 터치 어려움 0.890(B 0.850), 헤맴 0.821(0.791), 시각 어려움 0.645(0.573), 망설임 0.837(0.772), normal 0.772(0.688)입니다. 이 점수의 정답은 합성 터치 조건과 장면에 따라 정해집니다. 카메라 숫자와 질문 형식(값 정의 추가)이 함께 바뀌어 어느 쪽의 효과인지는 구별할 수 없습니다.

호출은 9,448번(smoke 219번, 전체 9,229번), 실패는 0번, 비용은 $1.103입니다(입력 10억 토큰당 $42, 출력 무료: `docs/Jev-Integration.md` 3장).

## 실행

입력(비전 재생 기록, 앞선 Jev 실험의 실행기 `run_jev_ablation.py`와 채점기 `metrics.py`, 정렬된 창 입력, 라벨 v5)은 저장소에 없고 비전 담당 작업 폴더에 있습니다. `run_raw.py`는 Jev 키를 환경 변수 `JEV_API_KEY`에서 읽고, 없으면 `backend/.env`에서 읽습니다.

도구는 비전 담당 작업 폴더의 배치를 기준으로 경로를 잡습니다. 그래서 저장소 안에서 바로 실행되지는 않고, 아래 명령은 실험 때 돌린 순서를 보여 줍니다.

```powershell
$W  = "experiments\eval_jev_raw_2026-11-08"
$PY = "<backend 가상환경>\Scripts\python.exe"   # 앞선 Jev 실험의 backend 가상환경(PR #77, 커밋 3c936ae)
$AI = "ai-engine\.venv\Scripts\python.exe"      # 채점(numpy 필요)
$PREV = "<앞선 Jev 실험의 기록 실행 폴더>"       # 비전 담당 작업 폴더에 있음(읽기만)
# (a) stub: API 호출 없음(약 7초)
& $PY -B "$W\tools\run_raw.py" --jev stub --stub-model jev-1.13.0 --out "$W\results\a_stub_full"
& $PY -B "$W\tools\check_run.py" --run "$W\results\a_stub_full"
# (b) smoke: 실제 API, 영상 1개
& $PY -B "$W\tools\run_raw.py" --jev real --takes 20261028_171348 --cache-file "$W\results\jev_cache_e12.jsonl" --out "$W\results\b_smoke_171348" --max-calls 400
python -B "$W\tools\cost_report.py" --run "$W\results\b_smoke_171348" --projection "$W\results\a_stub_full"
# (c) 전체: 실제 API
& $PY -B "$W\tools\run_raw.py" --jev real --cache-file "$W\results\jev_cache_e12.jsonl" --out "$W\results\c_full" --concurrency 2 --max-calls 9800 --max-failure-rate 0.01
# 채점과 표: 호출 없음
& $AI -B "$W\tools\score_raw.py" --run "$W\results\c_full" --out "$W\results\c_full\labels_v5"
& $AI -B "$W\tools\score_raw.py" --run "$PREV\stage2_3_J_b0_r0" --out "$W\results\scoring_check\E5_J" --arms J
& $AI -B "$W\tools\score_raw.py" --run "$PREV\stage2_1_swap_C_C0" --out "$W\results\scoring_check\E5_C_C0" --arms C C0
python -B "$W\tools\make_table.py"
python -B "$W\tools\per_window.py" --run "$W\results\c_full" --out "$W\results\c_full"
```

실행 기록 파일에서 RAW-1과 RAW-2의 `condition`은 `J`입니다. 채점기가 condition J를 '지원 6개 + none 가운데 고르기'로 채점하기 때문이고, 조건 이름(RAW-1 · RAW-2)과 `JEV_STAGES`(`raw:...`)로 J와 구별합니다.

## 한계

- 앞선 Jev 실험과 같은 틀입니다. Jev의 선택은 뒤 창을 바꾸지 않는 그림자 모드이고, 녹화 속 사용자는 지원에 반응하지 않으며, 터치는 합성이고, 라벨 v5는 잠정입니다. 모델 버전은 `jev-1.13.0` 하나, 요약 형식과 값 정의 문장도 하나씩입니다.
- 어느 창을 물을지(측정 가능 여부)와 `session` 값(화면에 보이는 지원, 거둔 지원)은 규칙표 흐름에서 옵니다(J와 같음).
- 카메라 숫자만의 효과는 따로 재지 않았습니다. 카메라 숫자를 뺀 대조가 없고, RAW-2가 늘린 사례는 합성 터치 조건이 정한 사례입니다. 그래서 이 실험으로는 "카메라 숫자를 주면 규칙표보다 낫다"거나 "카메라 숫자가 RAW-2의 도움 증가를 만들었다"고 말할 수 없습니다.
- 실제 사용자에게 도움이 되는지는 보여 주지 않습니다(그림자 모드, 합성 터치, 지원에 반응하지 않는 녹화, 잠정 라벨).
- 3초 구간을 최솟값 · 중앙값 · 최댓값으로 줄여 구간 안의 순서가 없습니다. 고개를 몇 번 돌렸는지는 이 숫자로 셀 수 없습니다.
- yaw 부호(+ = 영상 오른쪽)는 비전 README의 풀이이고, 실제로 고개를 돌린 영상으로는 확인하지 않았습니다. 몸 점은 주 사용자가 아닌 사람을 따라갈 수 있습니다.
- 같은 요청은 첫 답을 다시 써서 Jev 답의 흔들림은 재지 않았습니다. 같은 요청이 동시에 두 번 나간 95개 가운데 고르기 질문 57개에서 선택이 바뀐 것은 1개입니다.
