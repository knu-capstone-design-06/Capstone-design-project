# 음성 화면 설정: 프론트 적용부

- 작성일: 2026-11-24
- 상태: **프론트 적용부 준비 / 서버 응답 미연결 / 계약 검토 필요**
- 기존 STT·음성 주문·자동 TTS는 그대로 사용합니다. 이 작업은 프론트에서 자연어를 해석하지 않습니다.

## 구현한 범위

`voiceSettings.ts`는 백엔드에서 검증한 명령을 프론트 내부 설정으로 옮기기 위한 적용 경계입니다. 요청 전에 `prepare()`로 적용 맥락을 잡고, 검증된 결과를 받은 뒤 반환된 함수를 한 번 호출하도록 준비했습니다. HTTP 응답이나 `tool_calls`에서 값을 꺼내는 어댑터는 아직 없습니다.

현재 `contract/voice.openapi.yaml`은 장바구니 도구와 `ui_changed` 이벤트 이름만 정의합니다. 변경할 설정값·켜기/끄기·UI 결과 식별자는 없습니다. `lowScreen`도 서버 프리셋이 아닙니다. 따라서 임의의 응답 필드를 읽거나 인식한 문장을 프론트에서 해석해 적용하지 않습니다.

아래 이름은 기존 `Settings`의 **프론트 내부 키**이며 새 API 계약이 아닙니다. 값은 `true`(켜기)와 `false`(끄기)만 받습니다.

| 키 | 기존 화면 기능 |
|---|---|
| `largeText` | 큰 글씨(200%) |
| `largeButton` | 큰 버튼 |
| `simpleScreen` | 간편 화면 |
| `stepGuide` | 단계별 안내 |
| `lowScreen` | 낮은 화면; 끄면 기본 높이 |
| `highContrast` | 고대비 |

- 여러 키는 함께 검사하고, 모르는 키·잘못된 값이 하나라도 있으면 전부 거절합니다. 이미 적용된 값에는 새 알림을 만들지 않습니다.
- 같은 응답과 같은 맥락에서 준비한 다른 응답을 중복 적용하지 않습니다.
- 새 세션·화면 이동·모달 진입·음성 모드 해제·음성 오류·주문 처리 중·페이지 숨김/이탈 뒤의 결과는 적용하지 않습니다. 다시 원래 화면으로 돌아와도 이전 적용 권한이 살아나지 않습니다.
- 현재 시안의 음성 설정은 세션 안에서만 유지하고, 새로고침·새 주문에서 해제합니다. 기존 수동 설정은 덮어쓰거나 영구 저장하지 않습니다. 정식 보관 정책은 팀 결정 대상입니다.
- [화면 위로 올리기]는 높이만 되돌립니다. 남은 음성 변경이 있을 때 [원래대로]를 누르면 그 변경을 해제하고 복귀 안내를 표시합니다. [기본 화면으로]는 기존 수동·서버 지원·음성 설정을 함께 초기화합니다.
- Cart를 쓰거나 다시 조회하지 않고, 설정 변경만으로 음성 모드를 끄거나 새 음성 요청·TTS를 실행하지 않습니다. 설정 변화는 기존 로컬 `ui_settings_change` 기록에 남습니다.

### 현재 프론트의 적용 순서

1. 저장된 수동 설정을 바탕으로 현재 세션에서 고객이 수락한 서버 지원 값을 합칩니다.
2. 같은 세션의 음성 변경을 그 위에 적용합니다. 음성 명령이 수동 설정과 수락한 서버 지원을 합친 값으로 돌아가면 그 키의 음성 변경을 해제합니다.
3. 고객이 터치로 설정을 바꾸면 해당 키의 서버 지원 값과 음성 변경을 해제합니다. 서버 지원을 새로 수락하면 해당 키의 음성 변경만 해제합니다. 다른 키에 적용된 음성 변경은 유지합니다.

## 개발 빌드에서 재현

기본 API 모드에서 세션이 준비된 뒤 [말로 주문하기]를 켭니다. 개발자 도구에서 다음을 실행합니다.

```js
// 요청 전의 프론트 맥락. 이 객체/함수는 네트워크 전송 형식이 아닙니다.
const finish = window.kioskVoiceSettingsDraft.prepare();

// 백엔드 검증 완료를 가정한 프론트 내부 값 주입.
finish?.({ largeText: true, largeButton: true, lowScreen: true });

// 이미 소비한 요청이라 false입니다.
finish?.({ highContrast: true });

// 새 맥락에서 높이만 복귀합니다.
window.kioskVoiceSettingsDraft.prepare()?.({ lowScreen: false });
```

`kioskVoiceSettingsDraft`는 개발 빌드에만 있습니다. 배포 빌드에서는 이 진입점이 제거됩니다. 현재 실제 발화와 `ui_changed` 이름만으로 화면을 바꾸지는 않습니다.

## 다른 담당자에게 요청할 연결

- **AI:** 화면 설정 의도와 켜기/끄기·복귀를 해석하고, 부정·모호한 요청·장바구니 주문과 섞인 요청을 검증하는 명령 생성. 프론트가 인식문이나 `reply_text`를 다시 해석하지 않도록 결과를 구조화해야 합니다.
- **백엔드·AI:** 음성 API의 UI 결과 필드·허용 값·세션/요청 식별·확인 전 제안과 실행 가능 결과를 구분하는 계약. `ui_changed` 이름만으로는 어떤 설정을 적용할지 알 수 없습니다. Cart와 UI 명령의 부분 성공·실패 및 중복 처리도 정해야 합니다.
- 계약이 정해지면 프론트가 요청 시점의 맥락을 잡고, 백엔드가 검증한 적용 가능 결과만 위 경계에 넘기는 어댑터를 연결합니다. 현재 장바구니 `tool_calls`를 UI 명령으로 실행하지 않습니다.

### 프론트·백엔드·AI 공동 결정 항목

- **프리셋 또는 설정별 켜기·끄기.** [음성 연동 검토 문서](../../../../docs/Voice-MCP-Implementation.md)는 `set_ui_preset`과 `ui_changed`의 `{ preset?, screen_id? }`를 제안합니다. [현재 프론트·백엔드 계약의 `UIPreset`](../../../../contract/frontend-backend.openapi.yaml)은 설정을 켜는 프리셋만 제공하며 낮은 화면과 고대비는 포함하지 않습니다. 프리셋을 끄기·낮은 화면·고대비까지 확장할지, 설정별 불리언으로 켜기와 끄기를 표현할지 정합니다.
- **적용 우선순위와 복귀.** 위 프론트의 적용 순서를 정식 연동에도 사용할지, 어떤 변경에 고객 확인이 필요한지 정합니다. 새 주문과 새로고침에서 설정별 유지 범위와 적용 성공·실패 안내도 함께 정합니다.
- **설정 변경 출처.** 현재 로컬 `ui_settings_change`는 변경 전후 값만 저장하고, 공동 파일럿의 `touch.interaction.ui_settings_change_count`는 설정 변경을 출처 구분 없이 집계합니다. 터치로 직접 바꾼 설정, 수락한 서버 지원, 음성 변경을 원시 기록에 구분할지, 판단 층에 보내는 집계에도 반영할지 정합니다. [터치 로그 검토](../../../../docs/Touch-Log-Review.md)를 참고합니다.

## 검증

`frontend/`에서 기존 의존성으로 실행합니다. 새 의존성이나 환경변수는 추가하지 않았습니다.

```sh
npm test
node src/features/order/voiceSettings.test.mjs
node src/features/order/voiceWait.integration.test.mjs
npm run build
```

Vite 서버와 외부 Playwright 환경이 준비돼 있으면 다음으로 프론트 화면을 확인합니다. 기존 브라우저 검사와 같은 `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHANNEL`, `ORDER_BROWSER_URL`을 사용합니다.

```sh
node --test-name-pattern='음성 설정 적용부' src/features/order/voiceMode.browser.test.mjs
```

1080×1920 Chromium에서 기본 글씨·낮은 화면, 큰 글씨·큰 버튼·낮은 화면, Cart 유지, 수동 설정 우선, 초기화·새로고침, 중복·지연 응답을 검사합니다. 음성 설정이 모두 복귀하면 [원래대로]가 사라지는지, 서버 지원을 수락하면 해당 설정만 음성 값에서 해제되는지, 마우스와 터치에서 복귀 안내가 표시되는지도 확인합니다. HTTP 응답·음성 인식·합성은 모의 객체입니다. 실제 AI의 화면 명령 생성과 시험 기기·마이크·스피커는 후속 검증 범위입니다. 대표 화면은 [검증 기록](../../../../docs/screenshots/voice-settings-2026-11-24/README.md)에 있습니다.
