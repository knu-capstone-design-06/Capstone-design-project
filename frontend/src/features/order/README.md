# 상품·장바구니·모의 주문 프론트 연동 준비

현재 OpenAPI 0.3.0 초안에 맞춰 상품 표시·서버 Cart 표시·주문 확인·서버 응답의 주문번호를 표시하는 프론트 코드를 준비했습니다. 백엔드 구현 완료·팀 전체 합의와 구분합니다. [검토 문서](../../../../docs/Product-Cart-Order-API-Draft.md)를 참고합니다.

- 기본 API 모드는 상품 가격·Cart 항목·총액에 서버 응답을 사용합니다. 개발용 샘플은 아래 설정으로 명시적으로 켤 수 있습니다.
- 추가·수량 변경·삭제는 성공 응답 뒤 확정 표시하고 요청 중 변경을 막습니다. 초안의 항목별 20개 한도를 화면에 적용했습니다.
- 응답 유실은 같은 키·버전·본문으로 ‘결과 다시 확인’을 실행합니다. 충돌은 최신 Cart를 표시하고 재조작에 새 키를 사용합니다.
- 재확인에도 실패하면 ‘처음부터 다시 주문’으로 대기 요청을 버리고 새 서버 세션을 시작할 수 있습니다. 첫 실패나 요청 처리 중에는 이 기능을 제공하지 않습니다. 이전 서버 주문을 취소하는 기능은 아니며 화면에 이를 안내합니다.
- 변경 요청의 코드 없는 404·410과 세션·접근 오류는 새 이용 시작을 안내합니다. 상품·장바구니 항목 없음 404는 기존 주문을 유지하고, 초기 주문 API 미구현은 연결 대기로 표시합니다.
- 처리 중 오류의 코드·보관 정책은 백엔드와 합의할 항목입니다. 서버의 409 + Retry-After가 있으면 수동 재시도 간격을 지킵니다.
- 주문번호는 서버 응답을 그대로 표시합니다. 프론트에서 번호를 발급하거나 서버 완료 상태를 저장하지 않습니다.
- 주문 성공 응답의 필수 필드·항목·수량·금액·생성 시각을 검증합니다. 불완전하거나 세션이 다르면 장바구니를 유지하고 같은 키·본문으로 결과를 다시 확인합니다.
- 완료 후 새 이용과 새로고침은 기존 세션 생성 API로 새 세션을 요청합니다. 접근성 설정만 로컬에 유지합니다.
- 기존 main의 세션 API를 사용하며 별도 백엔드 라우터·Cart 서비스·인증·저장소를 구현하지 않습니다.
- 상품·Cart·Order API가 없는 서버에서는 연결 대기를 표시합니다. 현재 main에는 해당 주문 API가 아직 없습니다.
- 음성·MCP·실제 결제·재고 차감은 포함하지 않습니다. 복원·장기 보관·정밀 만료·동적 가격은 후순위입니다.

큰 글씨·큰 버튼·간편 화면·단계별 안내와 로컬 터치 기록을 제공합니다. 새 서버 세션을 받을 때 로컬 로그도 새 세션으로 분리하고 시작 기록의 `server_session_id`와 각 이벤트의 `serverSessionId`에 연결 ID를 남깁니다. 새로고침은 이전 기록 버퍼를 보관하되 이전 세션을 이어 쓰지 않습니다. 연결 전·재연결 대기의 기록은 서버 ID가 null인 별도 로컬 세션입니다. 이 경계는 프론트 담당자의 작업 방향이며 팀의 서버 만료·복원 정책 합의를 뜻하지 않습니다.

## 실행

Node.js 22.18 이상에서 `frontend/`를 작업 디렉터리로 사용합니다.

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
```

Vite의 기존 `/backend/` 프록시를 사용합니다. 실제 주문 확인에는 백엔드 담당자의 주문 API 구현이 필요합니다.

## 개발용 샘플 모드

백엔드 주문 API가 준비되기 전에는 개발 서버 실행 시에만 샘플 응답 어댑터를 선택합니다.

```powershell
$env:VITE_ORDER_SAMPLE='true'
pnpm dev
```

화면에 ‘개발용 샘플 · 실제 결제 없음’을 표시하고 기존 17개 상품으로 옵션·수량·삭제·확인·완료·새 주문을 시연합니다. 개발 어댑터는 HTTP 응답과 같은 형태의 메모리 샘플을 제공합니다. `/backend/` 요청·서버 저장·실제 결제는 발생하지 않으며 주문번호는 `DEV-SAMPLE-`으로 구분합니다. 새로고침하면 샘플 주문 상태도 초기화합니다.

`VITE_ORDER_SAMPLE`을 지우거나 `false`로 설정하고 개발 서버를 다시 시작하면 기본 API 모드로 돌아갑니다. 서버 오류가 발생했다고 자동으로 샘플 모드로 전환하지 않습니다. 프로덕션 빌드·Docker 실행에서는 이 값이 `true`여도 샘플 어댑터를 사용하지 않습니다. 설정을 프로젝트의 `.env`에 저장하거나 새 의존성을 추가할 필요는 없습니다.

## 백엔드 없이 화면 검증

외부 Playwright 모듈을 제공하고 Vite를 실행합니다. 서비스 의존성에 Playwright를 추가하지 않습니다.

```powershell
$env:PLAYWRIGHT_MODULE='file:///절대경로/playwright/index.mjs'
$env:PLAYWRIGHT_CHANNEL='msedge'
$env:ORDER_BROWSER_URL='http://127.0.0.1:5173'
node --test src/features/order/order.browser.test.mjs
$env:TOUCH_LOG_BROWSER_URL=$env:ORDER_BROWSER_URL
node --test src/features/order/touchLog.browser.test.mjs
node --test src/features/order/touchLog.test.mjs
node --test src/features/order/sampleOrderApi.test.mjs
```

`PLAYWRIGHT_CHANNEL`을 지정하지 않으면 설치된 Microsoft Edge(`msedge`)로 실행합니다. 설치된 Google Chrome은 `chrome`, Playwright가 관리하는 Chromium은 `default`로 선택합니다. `default`는 실행 채널을 생략하므로 해당 Playwright 버전의 Chromium 브라우저가 미리 설치돼 있어야 합니다. 주문·터치 로그 테스트에 같은 설정을 사용합니다.

샘플 모드를 켠 별도 개발 서버를 `ORDER_SAMPLE_BROWSER_URL`, 빌드 후 `pnpm preview`로 연 화면을 `ORDER_PRODUCTION_URL`에 지정하면 추가 브라우저 테스트 2개를 실행합니다. 두 URL을 지정하지 않으면 해당 테스트만 생략합니다. 예: `$env:ORDER_SAMPLE_BROWSER_URL='http://127.0.0.1:5180'`, `$env:ORDER_PRODUCTION_URL='http://127.0.0.1:5181'`. 기본 API 모드 테스트의 `ORDER_BROWSER_URL`에는 샘플을 끈 서버를 지정합니다.

`orderApiFixture.mjs`는 요청 순서·내용을 확인하고 미리 준비한 HTTP 응답만 전달합니다. 실제 앱에서 import하지 않으며 서버 상품 공급·옵션 검증·Cart 변경·주문번호 발급 로직을 구현하지 않습니다.

프론트 상태/API 24개, 로컬 터치 기록 6개, 개발 샘플 3개의 단위 테스트와 TypeScript/Vite 빌드를 확인했습니다. 주문 브라우저 10개(샘플·프로덕션 URL을 지정한 경우)와 터치 기록 브라우저 3개는 Edge·Chrome에서 각각 모두 통과했습니다. 서버 실제 동작에 대한 검증 결과는 아닙니다.

- 상품 분류·iced/hot·푸드 null 요청과 화면 표시
- 응답 후 수량·금액 표시, 처리 중 버튼 차단
- 충돌 후 최신 Cart 표시·최신 버전·새 키
- 응답 유실의 같은 키·본문 재시도와 완료 번호 표시
- 새 이용 실패 후 재연결, 새로고침 시 새 세션·빈 Cart·설정 유지
- 새 서버 세션·새로고침의 로컬 로그 분리와 서버 ID 연결, 이전 버퍼 유지
- 불완전한 주문 성공 응답의 Cart 유지와 같은 요청 재확인
- 명시적인 개발 샘플에서 서버 없는 시연, 프로덕션에서 샘플 차단
- 주문 API 미구현 시 연결 대기
- 1080×1920 기본·큰 글씨·큰 버튼·옵션·확인·완료 화면과 터치 로그 유지

선택적으로 `ORDER_SCREENSHOT_DIR`에 스크린샷 저장 경로를 지정합니다. 실제 장비에서는 Windows·브라우저 100% 배율과 F11 전체 화면으로 최종 확인합니다. 실제 서버의 합산·품절·중복 방지·접근 통제는 백엔드 구현 후 별도 연동 검증합니다.
