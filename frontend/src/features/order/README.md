# 상품·장바구니·모의 주문 프론트 연동 준비

현재 OpenAPI 0.3.0 초안에 맞춰 상품 표시·서버 Cart 표시·주문 확인·서버 응답의 주문번호를 표시하는 프론트 코드를 준비했습니다. 백엔드 구현 완료·팀 전체 합의와 구분합니다. [검토 문서](../../../../docs/Product-Cart-Order-API-Draft.md)를 참고합니다.

- 상품 가격·Cart 항목·총액은 서버 응답을 사용합니다. 로컬에 상품 가격·주문 저장소를 만들지 않습니다.
- 추가·수량 변경·삭제는 성공 응답 뒤 확정 표시하고 요청 중 변경을 막습니다. 초안의 항목별 20개 한도를 화면에 적용했습니다.
- 응답 유실은 같은 키·버전·본문으로 ‘결과 다시 확인’을 실행합니다. 충돌은 최신 Cart를 표시하고 재조작에 새 키를 사용합니다.
- 처리 중 오류의 코드·보관 정책은 백엔드와 합의할 항목입니다. 서버의 409 + Retry-After가 있으면 수동 재시도 간격을 지킵니다.
- 주문번호는 서버 응답을 그대로 표시합니다. 프론트에서 번호를 발급하거나 서버 완료 상태를 저장하지 않습니다.
- 완료 후 새 이용과 새로고침은 기존 세션 생성 API로 새 세션을 요청합니다. 접근성 설정만 로컬에 유지합니다.
- 기존 main의 세션 API를 사용하며 별도 백엔드 라우터·Cart 서비스·인증·저장소를 구현하지 않습니다.
- 상품·Cart·Order API가 없는 서버에서는 연결 대기를 표시합니다. 현재 main에는 해당 주문 API가 아직 없습니다.
- 음성·MCP·실제 결제·재고 차감은 포함하지 않습니다. 복원·장기 보관·정밀 만료·동적 가격은 후순위입니다.

큰 글씨·큰 버튼·간편 화면·단계별 안내와 기존 로컬 터치 기록을 유지합니다. 터치 기록의 로컬 세션은 서버 주문 세션과 별도입니다.

## 실행

Node.js 22.18 이상에서 `frontend/`를 작업 디렉터리로 사용합니다.

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
```

Vite의 기존 `/backend/` 프록시를 사용합니다. 실제 주문 확인에는 백엔드 담당자의 주문 API 구현이 필요합니다.

## 백엔드 없이 화면 검증

외부 Playwright 모듈을 제공하고 Vite를 실행합니다. 서비스 의존성에 Playwright를 추가하지 않습니다.

```powershell
$env:PLAYWRIGHT_MODULE='file:///절대경로/playwright/index.mjs'
$env:ORDER_BROWSER_URL='http://127.0.0.1:5173'
node --test src/features/order/order.browser.test.mjs
$env:TOUCH_LOG_BROWSER_URL=$env:ORDER_BROWSER_URL
node --test src/features/order/touchLog.browser.test.mjs
node --test src/features/order/touchLog.test.mjs
```

`orderApiFixture.mjs`는 요청 순서·내용을 확인하고 미리 준비한 HTTP 응답만 전달합니다. 실제 앱에서 import하지 않으며 서버 상품 공급·옵션 검증·Cart 변경·주문번호 발급 로직을 구현하지 않습니다.

프론트 상태/API 19개, 로컬 터치 기록 단위 테스트 5개, 주문 브라우저 4개, 기존 터치 기록 브라우저 3개와 TypeScript/Vite 빌드를 확인했습니다. 서버 실제 동작에 대한 검증 결과는 아닙니다.

- 상품 분류·iced/hot·푸드 null 요청과 화면 표시
- 응답 후 수량·금액 표시, 처리 중 버튼 차단
- 충돌 후 최신 Cart 표시·최신 버전·새 키
- 응답 유실의 같은 키·본문 재시도와 완료 번호 표시
- 새 이용 실패 후 재연결, 새로고침 시 새 세션·빈 Cart·설정 유지
- 주문 API 미구현 시 연결 대기
- 1080×1920 기본·큰 글씨·큰 버튼·옵션·확인·완료 화면과 터치 로그 유지

선택적으로 `ORDER_SCREENSHOT_DIR`에 스크린샷 저장 경로를 지정합니다. 실제 장비에서는 Windows·브라우저 100% 배율과 F11 전체 화면으로 최종 확인합니다. 실제 서버의 합산·품절·중복 방지·접근 통제는 백엔드 구현 후 별도 연동 검증합니다.
