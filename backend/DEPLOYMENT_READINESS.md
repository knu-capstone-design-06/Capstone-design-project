## 연결 스모크 검사

백엔드와 ai-engine이 실행 중일 때 `backend/`에서 다음을 실행합니다. Python 표준 라이브러리만 사용합니다.

```powershell
python -m app.modules.connectivity.smoke --base-url http://127.0.0.1:8000
```

프론트 프록시를 거칠 때는 `--base-url http://127.0.0.1:8080/backend`로 같은 경로를 확인할 수 있습니다. 운영 HTTPS 진입점도 해당 URL을 넣습니다.

검사는 백엔드 생존, 백엔드→AI 상태 확인, 세션 생성, 특징 전송 후 AI 응답까지 순서대로 확인합니다. 실패하면 1을 반환하고 요청 경로(특징 전송 경로의 세션 ID는 `{session_id}`로 대체)와 오류 종류만 출력합니다. 세션 ID와 응답 본문은 출력하지 않습니다. HTTP 리디렉션은 따라가지 않고 오류로 처리합니다. 이 검사는 **DB 저장·주문·실제 비전 판단·자동 지원 완료·음성(OpenAI) 연결을 증명하지 않습니다.** 외부 AI API는 비용과 키 노출 위험이 있어 이 검사에서 호출하지 않습니다.

## 다음 구현 순서 제안

다음 순서는 팀 결정 사항이 아니라 검토용 제안입니다.

1. 팀과 주문 계약의 남은 세션 접근·만료, 처리 중 중복 요청, 성공·실패 기록 보관 정책을 확정합니다.
2. PR #73의 DB 저장 경로와 PR #67의 음성 변경을 통합하고 실제 프론트의 DB 모드 주문 흐름을 재검증합니다.
3. 비전 전달 계약과 지원 선택 정책이 합의되면 현재 연결 API에 실제 판단을 연결합니다.
4. 배포 HTTPS 경로에서 연결 스모크 검사와 재시작·장애·복구, 세션 접근 통제와 백업 주기, 보안·비용 점검을 수행합니다.
