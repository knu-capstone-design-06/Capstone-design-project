## 연결 스모크 검사

백엔드와 AI 서버가 실행 중일 때 `backend/`에서 다음을 실행합니다. Python 표준 라이브러리만 사용합니다.

```powershell
python -m app.modules.connectivity.smoke --base-url http://127.0.0.1:8000
```

프론트 프록시를 거칠 때는 `--base-url http://127.0.0.1:8080/backend`로 같은 경로를 확인할 수 있습니다. 운영 HTTPS 진입점도 해당 URL을 넣습니다.

검사는 백엔드 생존, 백엔드→AI 상태 확인, 세션 생성, 특징 전송 후 AI 응답까지 순서대로 확인합니다. 실패하면 1을 반환하고 요청 경로(특징 전송 경로의 세션 ID는 `{session_id}`로 대체)와 오류 종류만 출력합니다. 세션 ID와 응답 본문은 출력하지 않습니다. HTTP 리디렉션은 따라가지 않고 오류로 처리합니다. 이 검사는 **DB 저장·주문·실제 비전 판단·자동 지원 완료·음성(OpenAI) 연결을 증명하지 않습니다.** 외부 AI API는 비용과 키 노출 위험이 있어 이 검사에서 호출하지 않습니다.

## 다음 구현 순서 제안

다음 순서는 팀 결정 사항이 아니라 검토용 제안입니다.

1. 팀과 상품·장바구니·주문 계약의 미정 정책을 확정합니다. 특히 세션 접근, 만료, 버전 충돌, 중복 요청과 상품 가격·재고 정책을 결정합니다.
2. 확정 계약에 맞춰 상품·장바구니·모의 주문 API를 구현하고 프론트의 기본 API 모드와 통합 검증합니다. 첫 시연은 단일 프로세스 저장으로 검증할 수 있으나 재시작 시 데이터가 사라집니다.
3. Supabase 백엔드 접속 역할·비밀값 전달·세션 수명을 정한 뒤 새 마이그레이션과 저장소 코드를 추가합니다. 이미 병합된 마이그레이션은 수정하지 않습니다.
4. 비전 전달 계약·음성 PR과 지원 선택 정책이 합의되면 현재 연결 API에 실제 판단·명령 실행을 연결합니다.
5. 로컬 Compose와 배포 HTTPS 경로에서 연결 스모크 검사, 재시작·장애·복구, 보안·비용 점검을 수행합니다.
