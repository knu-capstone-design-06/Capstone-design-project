# Jev 큰 버튼 제안의 유효기간과 적용 기준

**상태 · 팀 검토 중**　|　**범위 · 큰 버튼을 켤지 사용자에게 묻는 제안 한 종류**

사용자가 메뉴 화면에서 버튼을 누르기 어려워 보일 때, 어느 관측까지 근거로 삼아 “버튼을 크게 바꿀까요?”라고 물어도 되는지 정한다. 큰 버튼은 사용자가 수락한 뒤 켠다. 아래 두 항목의 채택안과 결정 날짜를 각각 기록한다. 문서 병합 후에도 미결 항목은 검토 중으로 둔다.

## 출발점

- [공용 주문·특징 계약](../contract/frontend-backend.openapi.yaml)의 `SupportDecision`에는 `large_button`, `requires_confirmation`, `decided_by`가 있다. [현재 백엔드 응답 모델](../backend/app/modules/sessions/schemas.py)은 `none`을 반환한다.
- [판단 계층 PR #77](https://github.com/knu-capstone-design-06/Capstone-design-project/pull/77)은 질문한 창에 Jev 결과를 기록한다. 호출은 백그라운드에서 진행되어 해당 창의 `/features` 응답이 먼저 끝날 수 있다. 규칙에 필요한 ‘빗나간 뒤 바로잡은 횟수’는 현재 백엔드 입력에서 얻을 수 없다. 누락된 관측을 0이나 단순 빗나감 횟수로 채우면 제안 근거가 달라진다.
- 독립 검사에서는 #77의 후보 필터·응답 검증과 [프론트 PR #87](https://github.com/knu-capstone-design-06/Capstone-design-project/pull/87)의 주문 화면에 합성 관측과 모의 Jev 응답을 사용했다. 백엔드 21개 사례와 Edge 25개 검사에서 수락 전 크기 유지, 수락 후 확대, 세션 전환·장애 시 화면 유지를 확인했다. 실제 이용자에게 적합한 제안 시점과 정확도는 파일럿에서 측정해야 한다.

## 결정 1. 어느 창까지 유효한가?

메뉴 방문 중 첫 번째 관측 창에서 질문했는데, Jev의 답을 받기 전에 다음 창이 도착한 경우를 기준으로 비교한다.

| 선택지 | 화면에 전달할 조건 | 확인할 점 |
|---|---|---|
| A. 질문한 창까지만 | 같은 세션·화면 방문의 원래 창이 최신이고 그 창의 응답을 아직 보낼 수 있을 때만 제안한다. | 현재 비동기 방식에서 응답을 이미 보냈다면 폐기한다. 같은 요청에서 기다리기로 하면 허용 대기 시간과 타임아웃을 정한다. |
| B. 바로 다음 창까지 | 같은 세션·같은 화면 방문에서 **연속된 바로 다음 관측 창**까지 한 번만 전달한다. 전달 직전에 큰 버튼이 여전히 허용 후보인지 다시 검사한다. | 다음 창의 응답도 끝났거나 창이 누락·역전됐으면 폐기한다. 전송 중단 후 오래된 답이 나가지 않도록 실제 시간 상한과 기준 시계도 정한다. |

**공통 폐기 조건 제안.** 주문 완료·새 세션, 화면 전환, 같은 메뉴 재방문, 그사이 사용자가 직접 큰 버튼을 켰거나 제안을 거절한 경우에는 이전 답을 폐기한다. 같은 창 재전송으로 제안을 두 번 표시하지 않는다. 세션 ID와 화면 이름만으로 메뉴 재방문을 구분할 수 없으므로 방문·창을 어떻게 식별할지 프론트와 정한다. [터치 관측 창 합의안](Touch-Interaction-Contract-Proposal.md)

**결정에 필요한 수치.** 같은 기록에서 A와 B를 각각 대입해 제때 전달할 수 있었던 제안 수, 다음 창에서 후보가 사라진 수, 관측 종료부터 답 도착까지 걸린 시간을 비교한다. 전달할 수 있었던 제안이 적다는 이유만으로 유효기간을 늘리지 않는다.

## 결정 2. 어떤 근거에서 제안할 것인가?

1. **후보 확인.** 규칙표가 큰 버튼을 허용하고 Jev의 `support_choice`도 `large_button`을 선택한 경우만 검토한다. 전달 직전에도 측정 가능 여부, 사용자 설정과 최근 반응을 확인한다.
2. **판정에 쓸 값 선택.** AI 담당자는 선택 답의 `confidence`와 `probabilities.large_button` 중 어떤 값을 쓸지, 값의 의미와 선택 근거를 제안한다. 독립 검사의 `0.75`는 분기 동작 확인용 입력이다. [Jev 연동 설계](Jev-Integration.md)
3. **파일럿 평가.** 큰 버튼 제안이 적절했는지 라벨이 있는 창으로 후보 기준값별 **적절한 제안 / 불필요한 제안 / 놓친 제안** 수를 비교한다. 연속 창에서 같은 사용자에게 반복해서 묻는 횟수도 확인한다. 그림자 모드에서는 수락률을 관측할 수 없으므로 라벨 평가와 실제 제안 후 사용자 반응을 구분한다.
4. **채택 또는 보류.** 평가 근거가 충분하면 사용한 모델·질문 버전, 지표, 기준값, 적용 시점을 남긴다. 근거가 부족하면 그림자 모드를 유지하고 다음 평가 자료와 담당자를 정한다. Jev 장애·잘못된 답·기한 경과 때는 새 제안을 보내지 않고 기존 수동 설정을 유지한다.
