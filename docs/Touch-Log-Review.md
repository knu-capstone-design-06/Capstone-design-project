# 터치·상호작용 로그 검토 초안

- 작성일: 2026-10-05
- 최종 갱신일: 2026-10-25
- 상태: 팀 검토용 초안. 확정된 데이터 계약이 아니며, 로컬 수집·파일럿 집계의 구현·검증 기록은 7~11장에 구분합니다.
- 대상: 프론트엔드·백엔드·AI 담당자
- 목적: 수집할 원시 정보, 계산할 통계, 팀에서 결정할 기준을 구분합니다.

## 1. 현재 상태와 기준 문서

주문 화면은 기본적으로 서버 API 응답을 사용하며 개발용 샘플은 명시적으로 켤 수 있습니다. 최초 문서 작성 시 터치 로그 수집은 미구현이었으며, 2026-10-05 로컬 원시 수집 초안을 추가했습니다. 2026-10-11 프론트 담당자 요청으로 새 서버 세션과 로컬 로그 세션의 경계를 맞추고 서버 ID를 기록합니다. 현재는 보관 중인 원시 기록의 요약과 5개 지표의 로컬 파일럿 집계까지 구현했으며, 개발 창에서 확인·JSON 내보내기가 가능합니다. 현재 집계 기준은 11장에 기록합니다.

서버에는 집계 통계를 받는 `POST /api/v1/sessions/{session_id}/features`와 프론트 호출 함수가 있습니다. 이번 로컬 파일럿은 해당 API의 자동 호출에 연결하지 않았습니다. 원시 로그의 서버 전송·저장과 로컬 집계 결과의 Jev 연결도 미구현이며, 원시 로그·파일럿 집계 형식은 정식 계약이 아닙니다.

현재 계약은 `tap_count`, `miss_tap_count`, `repeat_tap_count`, `back_count`, `dwell_ms`를 정의합니다. 아래 원시 이벤트와 추가 통계의 필드명·타입·필수 여부·결측 표현은 아직 합의하지 않았습니다.

README는 터치 통계 계산을 백엔드 책임으로 설명하지만, 현재 계약은 프론트엔드 계산으로 명시합니다. 로컬 파일럿은 프론트엔드에서 계산하고 있으며, 정식 계산 담당과 전송 기준은 팀에서 합의하고 관련 문서를 맞춰야 합니다. 특히 로컬 파일럿의 미산출 값 `null`은 현재 서버의 정수 필드에 그대로 보낼 수 없습니다.

## 2. 프론트 담당자와 정한 작업 방향

아래는 프론트엔드 담당자와 2026-10-05에 정한 방향, 2026-10-11 새 서버 세션 연결, 2026-10-25 로컬 파일럿 집계를 반영한 현재 방향입니다. 팀 전체의 계약 합의와 구분합니다.

| 항목 | 작업 방향 |
|---|---|
| 수집 범위 | 로컬 원시 수집·요약·파일럿 집계·수동 JSON 내보내기까지. 서버 전송·저장·Jev 연결은 향후 범위 |
| 입력 방식 | 포인터의 `pointerType`·`isPrimary`를 기록. 반복 후보는 같은 입력 방식의 주 포인터끼리 비교 |
| 파일럿 집계 | 기본 최근 2초의 누름·대상 밖 누름·반복 후보·뒤로가기와 현재 방문의 전경 체류 누적 시간. 상세 정의는 11장 |
| 화면 방문 | 메뉴·주문 확인·주문 완료 사이 이동 시 새 방문 생성. 같은 화면 재방문도 새 방문 |
| 화면 내 변경 | 상품 분류 변경, 옵션 창 열기·닫기는 현재 방문 안의 이벤트로 기록 |
| 화면 높이 변경 | 낮은 화면 켜기·기본 높이 복귀는 현재 방문 안의 UI 설정 변경. 서버·로컬 세션과 담은 메뉴 유지 |
| 새로고침 | 이전 로그 버퍼만 복원. 이전 로컬 세션 종료 후 새 서버 세션에 새 로컬 세션 연결 |
| 새 주문 | 서버 세션이 바뀔 때 이전 로컬 세션 종료, 새 로컬 세션 생성 및 서버 ID 기록 |
| 연결 대기 | 연결 전·재연결 중 이벤트는 서버 ID가 null인 별도 로컬 세션. 서버 세션을 받으면 분리 |
| 주문 중 이탈 | 자동 종료 기준은 미정 |
| 작업 관리 | `feat/frontend`에서 작업 단위별 검증·커밋 |

화면 방문 예: 메뉴 방문 1 → 분류 변경·옵션 창 열기/닫기 → 주문 확인 방문 2 → 메뉴 방문 3.

로컬 세션은 한 주문 이용 흐름을 연결하는 단위이며 사용자 신원을 식별하지 않습니다. 현재 프론트는 서버 세션 변경에 맞춰 로컬 세션도 분리하고 해당 ID를 기록합니다. 서버의 세션 만료·완료·복원 정책과 정식 전송 형식은 향후 팀 계약에서 결정합니다.

## 3. 수집할 원시 정보 제안

원시 기록과 집계 통계를 분리합니다. 아래는 수집 후보이며 전송 스키마가 아닙니다.

| 기록 종류 | 원시 정보 후보 | 용도·주의사항 |
|---|---|---|
| 공통 맥락 | 이벤트 ID, 로컬 세션 ID, 화면 ID, 방문 ID, 발생 시각, 경과 시간, 당시 UI 설정 또는 설정 참조 | 중복 식별과 같은 방문·UI 상태 연결. 새로고침 전후 경과 시간의 기준은 검토 필요 |
| 포인터 입력 | `pointerdown` 시각·좌표·실제 대상, `pointerType`·`isPrimary`, 입력 종료·취소·중단과 관측한 최대 이동 거리 | 누름을 한 번 기록. `click`으로 같은 입력을 중복 집계하지 않음. 누름만으로 탭 완료나 실패를 확정하지 않음 |
| 조작 대상 | 대상 ID·종류·활성 상태, 당시 위치·크기 | 버튼 내부 여부와 주변 거리 계산. 좌표·경계는 같은 화면 기준 CSS 픽셀을 제안 |
| 영역 밖 입력 | 가장 가까운 조작 가능한 대상 후보, 경계까지 거리, 인접 대상의 모호함 | 배경 입력을 즉시 실패로 판정하지 않음. 가까운 대상이 의도한 대상임을 확정하지 않음 |
| 조작 결과 | 조작 ID·종류, 연결된 입력 ID, 시작·완료 시각, 결과·사유, 상태 변화 여부 | 성공·차단·오류·취소를 구분. 처리 중은 최종 결과 미정. 실행할 조작이 없는 배경 입력에는 실패 결과를 만들지 않음 |
| 화면·옵션·분류 | 화면 진입·이탈, 출발·도착 화면, 진입 당시 전경 여부·전경 전환, 옵션 창 열기·닫기와 상품, 분류 변경 | 이동 경로 및 옵션 창 구간 복원. 옵션 창은 별도 화면 방문으로 만들지 않음 |
| UI 지원 | 설정 변경 시각, 변경 전후 설정, 수동 변경 여부 | 향후 자동 지원 연결 시 제안·수락·거절·복귀도 검토. 현재 수동 설정과 구분 |
| 시스템 대기 | 요청 시작·종료와 결과 | 실제 서버 요청 연결 후 측정. 샘플 화면에서 서버 대기 값을 임의로 만들지 않음 |

조작 가능한 대상에는 버튼 외 링크 등도 포함하는 방향을 제안합니다. 비활성 대상은 별도로 기록하고, 주변 거리 계산에서는 제외하는 안을 검토합니다. 옵션 창 뒤에 가려진 대상도 제외하는 안을 검토합니다.

다른 조작 가능한 대상 내부 입력은 인접 버튼의 주변 입력으로 집계하지 않는 안을 제안합니다. 스크롤·취소 입력을 완료된 탭 통계에 포함할지는 별도 합의가 필요합니다.

## 4. 계산할 통계 제안

아래 10개 통계 중 기존 계약의 5개 필드는 로컬 파일럿으로 계산합니다. 구현된 범위와 팀 합의가 필요한 부분을 구분하며, 나머지 추가 통계는 기존 제안 상태를 유지합니다.

| 통계 | 의미 | 기존 계약·제안 및 검토 사항 |
|---|---|---|
| 전체 누름 수 | 관측 구간에 발생한 포인터 누름 | 로컬 `tap_count`는 최근 2초의 `pointer_start` 수. 취소·스크롤·비활성 대상 누름도 포함. 완료된 탭과의 관계는 팀 합의 필요 |
| 조작 영역 밖 입력 수·비율 | 조작 가능한 대상을 벗어난 입력 | 로컬 `miss_tap_count`는 최근 2초의 실제 버튼·링크 대상이 없는 누름 수. 원시 요약의 대상 밖 비율은 보관 중인 현재 세션 기준으로 별도 표시. 현재 계약의 대상 범위 확장은 합의 필요 |
| 버튼 주변 입력 수·비율 | 영역 밖 입력 중 합의한 거리 안에 들어온 입력 | 추가 제안. 거리·대상·인접 버튼 기준 합의 후 계산 |
| 조작 성공·차단·오류 수 | 실제 실행 결과 | 추가 제안. 결과별 판정 시점·사유와 취소 집계 여부 검토 |
| 반복 입력 수 | 합의한 반복 기준에 해당하는 입력 | 로컬 `repeat_tap_count`는 800ms·24 CSS px 기준의 추가 반복 누름 후보 수. 대상·입력 방식·종료 관측 조건은 11장. 정상 반복을 포함할 수 있으며 팀 기준은 미정 |
| 영역 밖 입력 후 같은 대상 조작 성공 수 | 주변 입력 뒤 가까운 대상 후보의 조작이 성공한 흐름 | 추가 제안. 대상 연결·시간 기준 합의 후 계산. 사용자 의도나 실패 후 회복을 확정하지 않음 |
| 화면 체류 시간 | 화면 방문과 관측 구간의 시간 | 로컬 `dwell_ms` 기본값은 현재 방문의 전경 체류 누적 ms. 옵션 창·대기는 전경이면 포함하고 백그라운드·페이지 중단은 제외. 정식 의미는 팀 합의 필요 |
| 마지막 성공 조작 이후 시간 | 성공 조작 없이 경과한 시간 | 추가 제안. 성공 이력이 없는 상태와 시간 0을 구분. 세션·방문 중 기준 범위 검토 |
| 뒤로가기·재방문 수 | 화면 이동 흐름 | 로컬 `back_count`는 최근 2초의 주문 확인(`review`) → 메뉴(`menu`) 이동 수만 계산. 뒤로가기 대상 행동과 재방문 정의 합의 필요 |
| 시스템 대기 시간 | 요청 처리 때문에 기다린 시간 | 추가 제안. 향후 서버 연동 시 측정. 중첩 요청·네트워크 실패의 처리 검토 |

버튼 주변 입력은 조작 영역 밖 입력의 부분집합입니다. 두 횟수를 더해 실패 횟수로 사용하지 않습니다. 각 비율은 분모를 명시하고, 입력이 없는 구간의 비율 표현도 합의합니다.

미정·미측정·미산출 값을 관측 결과 0으로 채우지 않습니다. 반복 입력 임계값과 `dwell_ms` 의미는 프론트 담당자가 선택한 로컬 파일럿 값으로만 구현했습니다. 정식 기준은 5장의 팀 합의 대상으로 유지하며, 원시 정보로 향후 재계산할 수 있게 준비합니다.

### 구현된 파일럿 기준에 대한 합의 제안 (2026-10-25)

아래는 현재 [로컬 집계 코드](../frontend/src/features/order/touchLogFeatures.ts)에 있는 기준을 회의에 제안하는 문장입니다. 프론트 담당자의 로컬 적용 선택을 팀 전체의 합의로 간주하지 않으며, 위 표의 합의 결과는 모두 **미정**으로 유지합니다.

- **T01 — 전체 누름:** 파일럿의 `tap_count`는 최근 2초의 `pointer_start` 횟수로 세고, 종료 이벤트와 `click`은 중복으로 더하지 않는 안에 합의를 제안합니다. 취소·스크롤로 이어진 입력과 비활성 대상 누름도 누름 시작 횟수에는 포함하며, 이를 조작 성공 횟수로 해석하지 않습니다.
- **T02 — 대상 밖 누름:** 파일럿의 `miss_tap_count`는 실제 버튼·링크 대상이 없는 누름만 세고, 비활성 대상 누름은 대상 밖 누름에 포함하지 않는 안에 합의를 제안합니다. 대상 판정 정보가 부족하면 해당 지표는 `null`로 둡니다.
- **T04 — 반복 후보:** 같은 화면 방문·입력 방식·대상의 연속된 주 포인터 누름에서 시작 시각 차이 **800ms 이하**, 시작 좌표 사이 거리 **24 CSS px 이하**를 파일럿 시작 기준으로 채택하는 안에 합의를 제안합니다. 두 입력 모두 손 뗌이 관측되고 각 입력의 관측한 최대 이동 거리가 24 CSS px 이내여야 하며, 취소·중단·연결된 스크롤·비활성 대상은 제외합니다. 첫 누름을 빼고 조건을 만족하는 추가 누름만 세며, 두 입력 모두 대상 밖인 경우도 후보에 포함합니다. 정상 수량 조절도 포함할 수 있으므로 불편·오류로 확정하지 않습니다.
- **T05 — 체류 시간:** `dwell_ms`는 **현재 화면 방문의 전경 체류 누적 시간(ms)**으로 두고, 새 방문에서 다시 시작하며 백그라운드·페이지 중단 시간은 제외하는 안에 합의를 제안합니다. 전경 상태의 옵션 창과 서버 대기는 포함합니다. 최근 2초 안의 체류 시간이나 마지막 성공 조작 이후 시간으로 해석하지 않습니다.
- **T08 중 뒤로가기 — 이동 범위:** 파일럿의 `back_count`는 최근 2초의 **주문 확인(`review`) → 메뉴(`menu`)** 화면 이동만 세는 안에 합의를 제안합니다. 마지막 성공 이후 시간과 일반 재방문 횟수는 기존 미정 항목으로 둡니다.
- **T13 — 집계 구간·미산출:** 횟수 지표 4개는 현재 로컬 세션의 **최근 2초 `(집계 시각 - 2000ms, 집계 시각]`**를 기준으로 하고, 구간 전체의 연속 전경 관측이 없으면 `null`로 두는 안에 합의를 제안합니다. 각 지표에 필요한 기록이 부족한 경우에도 `null`로 두고, 관측 가능한 구간에서 발생하지 않은 경우만 0으로 표시합니다. `dwell_ms`는 이 2초 구간과 별개인 방문 누적 값입니다.

24 CSS px는 반복 후보의 거리 기준입니다. T03의 버튼 주변 입력 거리 기준은 그대로 미정이며, 위 제안 외 미구현 항목의 검토 내용은 변경하지 않습니다. 팀 합의 후 정식 계약과 구현의 후속 반영 범위를 정합니다.

### 기록 형식

모든 이벤트에 `id`, `sessionId`, `serverSessionId`, `occurredAt`, `elapsedMs`, `screen`, `visitId`, `settings`, `kind`, `data`를 기록합니다. `serverSessionId`는 연결된 서버의 `session_id`이며 연결 전에는 null입니다. `session_start.data.server_session_id`에도 같은 ID를 남깁니다. 이 이름은 로컬 코드 초안용이며 확정 계약이 아닙니다. `elapsedMs`는 세션 시작 시각부터의 벽시계 경과 시간으로, 화면 체류 시간인 `dwell_ms`가 아닙니다. 기기 시계 변경 영향은 정식 시각 정책에서 검토해야 합니다.

2026-10-13 추가한 낮은 화면은 기존 `settings` 복사본의 `lowScreen` 불리언으로 기록합니다. `true`는 낮은 화면, `false`는 기본 높이이며 전환 시 기존 `ui_settings_change.data.before/after`에 반영합니다. ‘기본 높이’는 이 값만 바꾸고 ‘기본 화면’은 모든 설정을 초기화합니다. 이전 이벤트에 필드가 없으면 당시 높이를 추측해 덧붙이지 않습니다. 이 로컬 설정 필드는 서버 전송 계약에 추가한 값이 아닙니다.

| `kind` | 기록한 내용 |
|---|---|
| `pointer_start` | 시작 좌표, 실제 버튼·링크의 ID·활성 상태·사각 경계. 영역 밖이면 가장 가까운 활성 대상 후보와 경계까지 거리. 동률 후보는 모두 보관 |
| `pointer_end` | 시작 이벤트 ID, 시작·종료 좌표, 마지막 관측 좌표, 시작점에서의 최대 관측 이동 거리, 취소 여부 |
| `pointer_interrupted` | 페이지 이탈 당시 끝나지 않은 입력의 시작 ID·마지막 관측 좌표 |
| `scroll` | 스크롤 컨테이너, 이전·이후 스크롤 위치, 시간상 겹친 입력 후보 ID |
| `screen_enter`, `screen_leave` | 화면 방문 시작·종료와 이동 사유. 분류·옵션 창은 새 방문으로 분리하지 않음 |
| `category_change`, `options_open`, `options_close` | 분류 변경 전후, 옵션 창 대상 상품 ID |
| `ui_settings_change` | 설정 변경 전후 값. 다른 입력에도 당시 설정 복사본 포함 |
| `session_start`, `session_resume`, `session_suspend`, `session_end` | 페이지 시작·서버 세션 변경에 따른 시작/종료·페이지 이탈 일시 중단. `session_resume`은 같은 서버 세션의 브라우저 뒤로가기 캐시 복귀 |

좌표·거리는 화면 기준 CSS 픽셀입니다. 버튼 내부·경계까지의 거리는 0이며 버튼 바깥은 사각형 경계까지의 최단 거리를 계산합니다. 이동 거리는 전체 경로 길이가 아닌 시작점 대비 최대 관측 변위입니다. 임계값이나 성공·실패 판정은 붙이지 않습니다.

낮은 화면에서도 좌표 원점은 전체 브라우저 뷰포트의 왼쪽 위입니다. 1080×1920에서 조작 영역이 y=768부터 시작해도 768을 빼거나 영역 비율로 정규화하지 않습니다. 당시 DOM 경계와 컨테이너 잘림을 관측하며 목록·주문 내역은 문서 대신 내부 `main`에서 스크롤할 수 있습니다. 높이 전환만으로 `screen`·`visitId`를 새로 만들지 않으며, 메뉴·주문 확인·완료의 실제 이동에는 기존 방문 규칙을 적용합니다.

낮은 화면의 위쪽 안내 영역은 기록 루트(`.kiosk`) 밖이므로 현재 이 영역의 터치는 기록하지 않습니다. 따라서 낮은 화면의 기록을 전체 뷰포트에서 발생한 입력 전체로 해석하지 않습니다. 상단 영역까지 수집할지는 팀 검토 후 결정합니다. 이 설명은 2026-10-14 PR #43의 AI 담당자 리뷰를 반영한 현재 수집 범위 기록이며, 팀의 수집 정책 합의와 구분합니다.

취소 입력은 실제 손을 뗀 위치를 알 수 없으므로 `end: null`로 기록하고 마지막 관측 좌표를 별도로 남깁니다. `pointercancel`만으로 스크롤이라고 판정하지 않습니다. 스크롤은 별도 이벤트로 남기며 활성 입력 또는 취소 후 아직 종료가 관측되지 않은 입력을 후보로 연결합니다. 다중 입력·프로그램 스크롤 때문에 이 연결은 원인이나 의도를 확정하는 값이 아닙니다. 손을 뗀 뒤 관성 스크롤 등에는 후보가 없을 수 있습니다.

버튼·링크의 표시 여부와 활성 상태를 확인하며 옵션 창이 열려 있으면 옵션 창 안에서만 주변 후보를 찾습니다. 다른 조작 대상 내부 입력에는 주변 후보를 붙이지 않습니다. 현재 사각 경계 관측은 복잡한 가림·클리핑·회전 모양을 완전히 판정하지 못하므로 정식 대상 정책은 T02에서 검토합니다.

전체 폭의 하단 고정 주문 바에 가려진 영역은 후보의 `visibleRect`에서 제외합니다. 완전히 가려진 버튼은 후보에서 빼고, 일부가 보이면 남은 사각 영역까지의 거리를 계산합니다. 주문 바 내부 버튼과 그 위에 뜬 옵션 창의 버튼에는 이 잘림을 적용하지 않습니다. 임의의 겹침 요소 전체를 판정하는 기능은 아니며 T02의 정식 대상 정책은 미정입니다.

### 로컬 보관과 확인

초안에서는 같은 탭의 `sessionStorage`에 `kiosk-touch-log-draft-v1` 키로 저장합니다. 새로고침에는 이전 기록 버퍼를 보관하지만 새 서버 세션에 맞춰 로컬 세션 ID를 새로 만듭니다. 새 주문·재연결에서도 서버 ID가 바뀔 때 이전 로컬 세션을 종료하고 분리합니다. 경계를 넘는 진행 중 입력은 중단 기록으로 마무리합니다. 서버 ID가 없는 이전 초안 이벤트는 null로 복원하며 연결을 추측하지 않습니다. 탭 종료 후 지속 보관은 보장하지 않습니다. 페이지 이탈은 일시 중단으로 기록하며 같은 서버 세션의 브라우저 뒤로가기 캐시 복귀에는 새 방문을 기록합니다.

개발용 임시 제한은 최신 이벤트 **1,000개**이며, 초과 시 오래된 기록부터 제거합니다. 이는 팀의 보관 정책이나 반복·거리 판정 기준이 아닙니다. 저장 실패 시 메모리 수집을 계속하고 확인 API의 상태로 알립니다. 로컬 보관·삭제·내보내기 정책은 T10에서 확정해야 합니다.

주문 화면을 연 브라우저의 개발자 도구 콘솔에서 확인합니다.

```js
window.kioskTouchLogDraft.read();       // 세션과 이벤트 복사본
window.kioskTouchLogDraft.status();     // 복원·저장 문제, 정상일 때 null
window.kioskTouchLogDraft.exportJson(); // 현재 버퍼 JSON 다운로드
```

이 개발 API는 주문 화면이 마운트된 동안 제공됩니다. 로그 초기화가 필요하면 개발자 도구의 Session Storage에서 해당 키만 삭제하고 새로고침합니다. 현재 주문 화면은 localStorage에서 장바구니를 복원하지 않으며 접근성 설정만 별도로 유지합니다.

## 11. 프론트 로컬 파일럿 집계 (2026-10-25)

현재 로컬 코드에는 반복 기준 **800ms·24 CSS px**, `dwell_ms`를 **현재 화면 방문의 전경 체류 누적 시간(백그라운드·페이지 중단 제외)**으로 적용했습니다. 이는 로컬 실험의 시작값이며 T01~T14에 대한 팀 전체의 합의나 서버 계약 확정이 아닙니다.

### 구현된 5개 지표와 관측 조건

[`touchLogFeatures.ts`](../frontend/src/features/order/touchLogFeatures.ts)의 기본 정책은 `repeatMs: 800`, `repeatPx: 24`, `dwellMode: 'foreground_visit'`이며, 기본 집계 구간은 2000ms입니다.

| 필드 | 현재 로컬 코드의 계산 범위 |
|---|---|
| `tap_count` | 현재 세션의 최근 2초에 발생한 `pointer_start` 수. 손 뗌 여부와 무관하며 취소·스크롤·비활성 대상 누름도 포함 |
| `miss_tap_count` | 같은 구간의 누름 중 실제 버튼·링크 대상이 `null`인 횟수. 비활성 대상은 별도 대상이므로 제외 |
| `repeat_tap_count` | 같은 방문·입력 방식·대상인 연속 누름 쌍이 800ms·24 CSS px 조건을 만족할 때 뒤쪽 누름을 1회로 계산. 같은 대상 밖 누름도 비교. 주 포인터·종료 관측·이동 거리 조건을 적용하고 취소·중단·연결된 스크롤·비활성 대상은 제외 |
| `back_count` | 같은 구간의 `screen_enter` 중 출발 화면이 `review`, 도착 화면이 `menu`인 이동 수 |
| `dwell_ms` | 현재 화면 방문에서 전경 상태였던 시간의 누적 ms. 새 방문에서 초기화. 백그라운드·페이지 중단은 제외하며 옵션 창·서버 대기는 전경이면 포함 |

횟수 지표는 최근 2초 전체의 연속 전경 관측이 있어야 계산합니다. 관측 구간이 부족하거나 해당 지표에 필요한 대상·입력 방식·종료 정보가 없으면 `null`로 표시하며, 관측한 0과 구분합니다. `dwell_ms`는 방문 시작과 전경 관측 정보로 별도 계산하므로 최근 2초 관측이 부족해도 산출될 수 있습니다. 시각이 잘못되거나 역전된 기록은 지표를 미산출로 처리합니다. 새 세션에는 이전 세션 기록을 섞지 않으며, 화면 이동·전경 전환·페이지 중단은 반복 후보의 연결을 끊습니다.

구간 직전의 선행 누름이 같은 방문에서 현재 구간의 누름과 반복 시간 기준 안에 있으면 그 정보도 필요합니다. 이 선행 누름의 `isPrimary`·대상·종료 등 필수 정보가 부족할 때 `repeat_tap_count`는 반복 없음(0)이 아닌 미산출(`null`)입니다.

원시 기록에는 `pointerType`·`isPrimary`, 입력 종료 시 관측한 최대 이동 거리, `screen_enter.data.visibility`와 `visibility_change`를 추가했습니다. 이전 기록에 없는 값은 추측해 채우지 않습니다. 반복 후보는 정상 수량 조절 등을 포함할 수 있으며 불편·오류 판정이 아닙니다.

### 로컬 요약·개발 확인·내보내기

- [`touchLogSummary.ts`](../frontend/src/features/order/touchLogSummary.ts)는 버퍼에 보관 중인 현재 세션의 누름·종료·취소·중단·스크롤과 방문별 기록을 요약합니다. 최대 1000개 버퍼이므로 오래된 기록이 빠졌다면 세션 전체 합계가 아닙니다. 대상 밖 비율의 분모는 보관 중인 현재 세션의 전체 누름 시작 수이며, 누름이 없거나 대상 판정이 누락되면 비율은 `null`입니다. 위의 최근 2초 파일럿 횟수와 범위가 다릅니다.
- [`useTouchLog.ts`](../frontend/src/features/order/useTouchLog.ts)의 `window.kioskTouchLogDraft.summarize()`로 원시 요약, `.features()`로 기본 파일럿 집계를 확인합니다. 원시 기록은 `.read()`, 저장 상태는 `.status()`, 원시 JSON은 `.exportJson()`으로 확인합니다.
- [`TouchLogPanel.tsx`](../frontend/src/features/order/TouchLogPanel.tsx)의 개발 창에서 반복 시간·거리와 체류 정의를 바꿔 비교할 수 있습니다. ‘마지막 누름 이후 경과’ 비교 모드는 성공 여부를 판정하지 않으며, 미구현인 ‘마지막 성공 조작 이후 시간’을 대신하지 않습니다. 개발 창의 500ms 갱신은 화면 표시 주기이며 수집·전송 주기가 아닙니다. 개발 창 입력은 수집 대상에서 제외합니다.
- 별도 파일럿 내보내기는 정책·집계 시각 구간·세션 ID·관측 여부·산출 값을 포함한 `touch-features-pilot.json`이며 버전은 `touch-pilot-v1`입니다. 원시 `touch-log-draft.json`과 서버 계약은 유지하며 자동 통계 전송·지원 판단은 연결하지 않습니다.

세부 정의·파일·실행 방법과 PR #55 UI 반영 범위는 [주문 기능 README](../frontend/src/features/order/README.md#2026-10-25-로컬-파일럿-터치-집계와-pr-55-반영)에 기록합니다. 이번 구현 변경은 로컬 작업 트리에 두며 푸시하지 않습니다.
