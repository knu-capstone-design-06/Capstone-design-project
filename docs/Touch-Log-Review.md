현재 계약은 `tap_count`, `miss_tap_count`, `repeat_tap_count`, `back_count`, `dwell_ms`를 정의합니다. 아래 원시 이벤트와 추가 통계의 필드명·타입·필수 여부·결측 표현은 아직 합의하지 않았습니다.

README는 터치 통계 계산을 백엔드 책임으로 설명하지만, 현재 계약은 프론트엔드 계산으로 명시합니다. 담당 위치를 합의하고 관련 문서를 맞춘 뒤 해당 부분을 구현합니다.

## 2. 이번 대화에서 정한 작업 방향

아래는 프론트엔드 담당 사용자와 2026-10-05 대화에서 정한 방향입니다. 팀 전체의 계약 합의와 구분합니다.

| 항목 | 작업 방향 |
|---|---|
| 수집 범위 | 우선 로컬 수집·확인까지. 서버 전송·저장·Jev 연결은 향후 범위 |
| 입력 방식 | 키오스크 터치 사용을 전제로 입력 방식별 구분을 하지 않음 |
| 화면 방문 | 메뉴·주문 확인·주문 완료 사이 이동 시 새 방문 생성. 같은 화면 재방문도 새 방문 |
| 화면 내 변경 | 상품 분류 변경, 옵션 창 열기·닫기는 현재 방문 안의 이벤트로 기록 |
| 새로고침 | 로컬 세션 유지, 새 화면 방문 생성 |
| 새 주문 | '새 주문 시작'에서 이전 세션 종료, 새 로컬 세션 생성 |
| 주문 중 이탈 | 자동 종료 기준은 미정 |
| 작업 관리 | `feat/frontend`에서 완성된 작업 단위별 검증·커밋. 이번 문서는 로컬 커밋까지만 진행하며 push하지 않음 |

화면 방문 예: 메뉴 방문 1 → 분류 변경·옵션 창 열기/닫기 → 주문 확인 방문 2 → 메뉴 방문 3.

로컬 세션은 한 주문 이용 흐름을 연결하는 단위이며 사용자 신원을 식별하지 않습니다. 서버 세션과의 대응은 향후 계약에서 결정합니다.

## 3. 수집할 원시 정보 제안

원시 기록과 집계 통계를 분리합니다. 아래는 수집 후보이며 전송 스키마가 아닙니다.

| 기록 종류 | 원시 정보 후보 | 용도·주의사항 |
|---|---|---|
| 공통 맥락 | 이벤트 ID, 로컬 세션 ID, 화면 ID, 방문 ID, 발생 시각, 경과 시간, 당시 UI 설정 또는 설정 참조 | 중복 식별과 같은 방문·UI 상태 연결. 새로고침 전후 경과 시간의 기준은 검토 필요 |
| 포인터 입력 | `pointerdown` 시각·좌표·실제 대상, 입력 종료·취소 정보 | 누름을 한 번 기록. `click`으로 같은 입력을 중복 집계하지 않음. 누름만으로 탭 완료나 실패를 확정하지 않음 |
| 조작 대상 | 대상 ID·종류·활성 상태, 당시 위치·크기 | 버튼 내부 여부와 주변 거리 계산. 좌표·경계는 같은 화면 기준 CSS 픽셀을 제안 |
| 영역 밖 입력 | 가장 가까운 조작 가능한 대상 후보, 경계까지 거리, 인접 대상의 모호함 | 배경 입력을 즉시 실패로 판정하지 않음. 가까운 대상이 의도한 대상임을 확정하지 않음 |
| 조작 결과 | 조작 ID·종류, 연결된 입력 ID, 시작·완료 시각, 결과·사유, 상태 변화 여부 | 성공·차단·오류·취소를 구분. 처리 중은 최종 결과 미정. 실행할 조작이 없는 배경 입력에는 실패 결과를 만들지 않음 |
| 화면·옵션·분류 | 화면 진입·이탈, 출발·도착 화면, 옵션 창 열기·닫기와 상품, 분류 변경 | 이동 경로 및 옵션 창 구간 복원. 옵션 창은 별도 화면 방문으로 만들지 않음 |
| UI 지원 | 설정 변경 시각, 변경 전후 설정, 수동 변경 여부 | 향후 자동 지원 연결 시 제안·수락·거절·복귀도 검토. 현재 수동 설정과 구분 |
| 시스템 대기 | 요청 시작·종료와 결과 | 실제 서버 요청 연결 후 측정. 샘플 화면에서 서버 대기 값을 임의로 만들지 않음 |

조작 가능한 대상에는 버튼 외 링크 등도 포함하는 방향을 제안합니다. 비활성 대상은 별도로 기록하고, 주변 거리 계산에서는 제외하는 안을 검토합니다. 옵션 창 뒤에 가려진 대상도 제외하는 안을 검토합니다.

다른 조작 가능한 대상 내부 입력은 인접 버튼의 주변 입력으로 집계하지 않는 안을 제안합니다. 스크롤·취소 입력을 완료된 탭 통계에 포함할지는 별도 합의가 필요합니다.

## 4. 계산할 통계 제안

| 통계 | 의미 | 기존 계약·제안 및 검토 사항 |
|---|---|---|
| 전체 누름 수 | 관측 구간에 발생한 포인터 누름 | 기존 `tap_count` 집계 기준 명확화. 누름 시작과 완료된 탭의 관계 합의 |
| 조작 영역 밖 입력 수·비율 | 조작 가능한 대상을 벗어난 입력 | 기존 `miss_tap_count` 보완. 현재 계약은 버튼 밖 터치 횟수이며 대상 범위 확장은 합의 필요 |
| 버튼 주변 입력 수·비율 | 영역 밖 입력 중 합의한 거리 안에 들어온 입력 | 추가 제안. 거리·대상·인접 버튼 기준 합의 후 계산 |
| 조작 성공·차단·오류 수 | 실제 실행 결과 | 추가 제안. 결과별 판정 시점·사유와 취소 집계 여부 검토 |
| 반복 입력 수 | 합의한 반복 기준에 해당하는 입력 | 기존 `repeat_tap_count`. 시간·거리·대상·정상 반복 기준 합의 전 계산 보류 |
| 영역 밖 입력 후 같은 대상 조작 성공 수 | 주변 입력 뒤 가까운 대상 후보의 조작이 성공한 흐름 | 추가 제안. 대상 연결·시간 기준 합의 후 계산. 사용자 의도나 실패 후 회복을 확정하지 않음 |
| 화면 체류 시간 | 화면 방문과 관측 구간의 시간 | 기존 `dwell_ms`. 방문 누적 또는 구간 내 시간, 옵션 창·대기·백그라운드 포함 여부 합의 필요 |
| 마지막 성공 조작 이후 시간 | 성공 조작 없이 경과한 시간 | 추가 제안. 성공 이력이 없는 상태와 시간 0을 구분. 세션·방문 중 기준 범위 검토 |
| 뒤로가기·재방문 수 | 화면 이동 흐름 | 기존 `back_count` 보완. 뒤로가기 대상 행동과 재방문 정의 합의 필요 |
| 시스템 대기 시간 | 요청 처리 때문에 기다린 시간 | 추가 제안. 향후 서버 연동 시 측정. 중첩 요청·네트워크 실패의 처리 검토 |

버튼 주변 입력은 조작 영역 밖 입력의 부분집합입니다. 두 횟수를 더해 실패 횟수로 사용하지 않습니다. 각 비율은 분모를 명시하고, 입력이 없는 구간의 비율 표현도 합의합니다.

미정·미측정·미산출 값을 관측 결과 0으로 채우지 않습니다. 원시 정보로 향후 재계산할 수 있게 준비하되, 반복 입력 임계값과 `dwell_ms` 의미는 추측해서 구현하지 않습니다.

## 6. 합의 결과와 후속 반영

팀 회의에서 결정한 항목은 아래에 남깁니다. 현재 팀 합의 완료 항목은 없습니다.

| 회의 날짜 | 검토 ID | 결정 내용·근거 | 참여 담당자 | 후속 작업·계약 반영 | 상태 |
|---|---|---|---|---|---|
| 미정 | — | — | — | — | 검토 대기 |

1. 회의 기록에 결정 근거와 참여자를 남기고 이 문서의 합의 결과를 갱신합니다.
2. 인터페이스 관련 결정은 `contract/`에 반영하고 영향받는 담당자의 리뷰를 받습니다.
3. 기존 공용 문서·코드 수정이 필요하면 사용자에게 대상과 변경 내용을 먼저 제안합니다.
4. 로컬 수집 → 서버 전송·저장 → 통계 계산 → Jev 입력·지원 전후 평가 순서로 작업 범위를 나눕니다. 각 단계는 필요한 기준을 합의한 뒤 검증·커밋합니다.

검토 항목에 대한 팀 합의 완료와 코드 초안 검증은 별개입니다. 원시 수집 초안의 검증 결과가 통계 계산이나 Jev 판단의 검증을 의미하지 않습니다.

## 7. 로컬 수집 코드 초안 구현 기록

- 구현일: 2026-10-05
- 범위: 주문 화면의 원시 이벤트 수집·로컬 확인·JSON 내보내기. 정식 계약이나 통계 계산은 구현하지 않음
- 입력 방식 구분, 반복·주변 거리 임계값, `dwell_ms`, 조작 성공·차단·오류 연결, 서버 요청·전송은 미구현

### 파일과 연결 방식

| 파일 | 역할 |
|---|---|
| [`touchLog.ts`](../frontend/src/features/order/touchLog.ts) | 로컬 세션·버퍼·기록 복사·거리 계산·저장 실패 상태 |
| [`useTouchLog.ts`](../frontend/src/features/order/useTouchLog.ts) | DOM 입력·스크롤 관측과 화면·옵션·분류·설정 기록, 개발 확인 API |
| [`OrderPage.tsx`](../frontend/src/features/order/OrderPage.tsx) | 훅 연결, 버튼·링크의 `data-log-target` 식별자, 새 주문 세션 분리 |
| [`touchLog.test.mjs`](../frontend/src/features/order/touchLog.test.mjs) | 거리·복원·세션 분리·저장 실패·기록 복사·버퍼 제한 검증 |
| [`touchLog.browser.test.mjs`](../frontend/src/features/order/touchLog.browser.test.mjs) | 실제 브라우저 주문 흐름·StrictMode·터치 스크롤 검증 |

기능 폴더 안에서 구현했으며 `src/app/`, `src/shared/`, 의존성·실행 스크립트는 변경하지 않았습니다. 화면 디자인과 기존 `onClick` 주문 처리는 유지합니다. `click`을 추가 누름으로 기록하지 않습니다.

### 기록 형식

모든 이벤트에 `id`, `sessionId`, `occurredAt`, `elapsedMs`, `screen`, `visitId`, `settings`, `kind`, `data`를 기록합니다. 이 이름은 로컬 코드 초안용이며 확정 계약이 아닙니다. `elapsedMs`는 세션 시작 시각부터의 벽시계 경과 시간으로, 화면 체류 시간인 `dwell_ms`가 아닙니다. 기기 시계 변경 영향은 정식 시각 정책에서 검토해야 합니다.

| `kind` | 기록한 내용 |
|---|---|
| `pointer_start` | 시작 좌표, 실제 버튼·링크의 ID·활성 상태·사각 경계. 영역 밖이면 가장 가까운 활성 대상 후보와 경계까지 거리. 동률 후보는 모두 보관 |
| `pointer_end` | 시작 이벤트 ID, 시작·종료 좌표, 마지막 관측 좌표, 시작점에서의 최대 관측 이동 거리, 취소 여부 |
| `pointer_interrupted` | 페이지 이탈 당시 끝나지 않은 입력의 시작 ID·마지막 관측 좌표 |
| `scroll` | 스크롤 컨테이너, 이전·이후 스크롤 위치, 시간상 겹친 입력 후보 ID |
| `screen_enter`, `screen_leave` | 화면 방문 시작·종료와 이동 사유. 분류·옵션 창은 새 방문으로 분리하지 않음 |
| `category_change`, `options_open`, `options_close` | 분류 변경 전후, 옵션 창 대상 상품 ID |
| `ui_settings_change` | 설정 변경 전후 값. 다른 입력에도 당시 설정 복사본 포함 |
| `session_start`, `session_resume`, `session_suspend`, `session_end` | 새 이용·새로고침 재개·페이지 이탈·새 주문에 따른 이전 세션 종료 |

좌표·거리는 화면 기준 CSS 픽셀입니다. 버튼 내부·경계까지의 거리는 0이며 버튼 바깥은 사각형 경계까지의 최단 거리를 계산합니다. 이동 거리는 전체 경로 길이가 아닌 시작점 대비 최대 관측 변위입니다. 임계값이나 성공·실패 판정은 붙이지 않습니다.

취소 입력은 실제 손을 뗀 위치를 알 수 없으므로 `end: null`로 기록하고 마지막 관측 좌표를 별도로 남깁니다. `pointercancel`만으로 스크롤이라고 판정하지 않습니다. 스크롤은 별도 이벤트로 남기며 활성 입력 또는 취소 후 아직 종료가 관측되지 않은 입력을 후보로 연결합니다. 다중 입력·프로그램 스크롤 때문에 이 연결은 원인이나 의도를 확정하는 값이 아닙니다. 손을 뗀 뒤 관성 스크롤 등에는 후보가 없을 수 있습니다.

버튼·링크의 표시 여부와 활성 상태를 확인하며 옵션 창이 열려 있으면 옵션 창 안에서만 주변 후보를 찾습니다. 다른 조작 대상 내부 입력에는 주변 후보를 붙이지 않습니다. 현재 사각 경계 관측은 복잡한 가림·클리핑·회전 모양을 완전히 판정하지 못하므로 정식 대상 정책은 T02에서 검토합니다.

### 로컬 보관과 확인

초안에서는 같은 탭의 `sessionStorage`에 `kiosk-touch-log-draft-v1` 키로 저장합니다. 새로고침에는 유지되지만 탭 종료 후 지속 보관은 보장하지 않습니다. 새 주문에서는 세션 ID를 새로 만들고 이전 이벤트도 버퍼 안에 유지합니다. 페이지 이탈은 세션 종료가 아닌 일시 중단으로 기록합니다. 브라우저 뒤로가기 캐시에서 복귀하면 새 방문을 기록합니다.

개발용 임시 제한은 최신 이벤트 **1,000개**이며, 초과 시 오래된 기록부터 제거합니다. 이는 팀의 보관 정책이나 반복·거리 판정 기준이 아닙니다. 저장 실패 시 메모리 수집을 계속하고 확인 API의 상태로 알립니다. 로컬 보관·삭제·내보내기 정책은 T10에서 확정해야 합니다.

주문 화면을 연 브라우저의 개발자 도구 콘솔에서 확인합니다.

```js
window.kioskTouchLogDraft.read();       // 세션과 이벤트 복사본
window.kioskTouchLogDraft.status();     // 복원·저장 문제, 정상일 때 null
window.kioskTouchLogDraft.exportJson(); // 현재 버퍼 JSON 다운로드
```

이 개발 API는 주문 화면이 마운트된 동안 제공됩니다. 로그 초기화가 필요하면 개발자 도구의 Session Storage에서 해당 키만 삭제하고 새로고침합니다. 장바구니가 저장된 localStorage는 별도입니다.

### 검증 결과와 재현

저장소 루트에서 새 단위 테스트를 실행합니다. 기존 `pnpm test` 스크립트에는 새 테스트를 추가하지 않았으므로 별도 실행이 필요합니다.

```sh
node --test frontend/src/features/order/touchLog.test.mjs
```

검증 결과: `frontend/`에서 `pnpm build` 통과, 기존 `pnpm test` 8개와 새 단위 테스트 5개 통과. 브라우저 통합 테스트 1개 통과: StrictMode 초기 기록 중복 방지, 누름·종료 각각 1회 기록, 모달 뒤 대상 제외, 옵션·설정 이벤트, 화면 방문 변경, 새로고침 세션 유지, 새 주문 세션 분리, 실제 터치 이동에 따른 `pointercancel` 및 스크롤 관측.

브라우저 테스트에는 실행 중인 Vite와 별도로 제공된 Playwright가 필요합니다. 서비스 의존성은 추가하지 않았습니다. 이번 검증은 번들 Playwright와 설치된 Edge의 headless 모드로 수행했습니다. Playwright 모듈 경로를 `PLAYWRIGHT_MODULE` 환경변수에 ESM import 가능한 경로로 지정하고 아래 파일을 실행합니다. URL은 기본 `http://127.0.0.1:5173`이며 `TOUCH_LOG_BROWSER_URL`로 변경할 수 있습니다.

```sh
node --test frontend/src/features/order/touchLog.browser.test.mjs
```

실물 키오스크의 터치 패널·관성 스크롤·저장 용량은 추가 수동 확인이 필요합니다. 배경 입력은 실패로, 시간상 겹친 스크롤은 확정된 스크롤 의도로 해석하지 않습니다.
