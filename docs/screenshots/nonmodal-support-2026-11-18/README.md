# 상품을 덮지 않는 초록색 지원 안내 바

- 날짜: 2026-11-18
- 대상: PR #70 `design` 로컬 작업본
- 요청: 제공된 참고 이미지처럼 낮은 가로 안내를 사용하고, 전체 화면의 초록색과 맞추되 상품을 가리지 않습니다.
- 촬영: Windows Microsoft Edge headless, 1080 × 1920 CSS px, device scale factor 1, 브라우저 확대율 100%.
- 범위: 개발 샘플 및 고정 HTTP 응답을 사용한 프론트 검증입니다. 실제 backend·AI 제안 생성과 G10의 F11 장비 검증은 포함하지 않습니다.

## 표시와 동작

짙은 초록색(`#163F35`) 바탕에 원형 아이콘·질문·흰 대답 버튼 두 개를 둡니다. 주문 바 위에 전용 공간을 확보해 상품·가격·분류·쪽 넘김·장바구니를 덮지 않습니다. 1080 × 1920에서는 빈 상태와 표시 상태의 높이를 맞춰 제안이 도착해도 상품 위치가 바뀌지 않습니다. 배경을 덮거나 키보드 초점을 옮기지 않습니다. 높이 900px 이하 개발 창에서는 빈 자리를 접고, 제안이 있을 때 하단 영역을 스크롤해 주문 버튼에 접근합니다.

[적용하기]는 제안한 항목만 켜고 [이대로 두기]는 해당 세션에서 그 항목을 거절합니다. Escape·바깥 누름은 이번 제안만 닫습니다. 바깥의 주문 조작은 첫 누름으로 실행합니다. 처음 500ms 동안의 제안 응답 보호는 유지합니다.

큰 글씨에서는 질문과 대답을 두 줄로 배치합니다. 글자·버튼 크기를 유지하며 메뉴 쪽 크기를 안내 공간에 맞춥니다. 낮은 화면에서 세로 공간이 부족하면 기존 목록 내부 스크롤로 나머지 상품과 쪽 넘김에 접근합니다. 안내 바와 주문 버튼은 아래 조작 영역 안에 남습니다. 고대비는 기존 토큰의 밝은 초록색 바탕과 검정 버튼을 사용합니다.

## 검증

- 기본·큰 버튼·큰 글씨/큰 버튼·낮은 화면/확대/고대비에서 제안 도착 전후 상품 좌표와 크기가 같은지 검사합니다.
- 안내가 목록 영역 밖에 있으며 가로 넘침·문서 세로 넘침·모달이 없는지 검사합니다. 낮은 화면의 목록은 내부에서 스크롤합니다.
- 제안 중 상품·분류·수량·주문 확인을 첫 누름에 실행하고, 그 입력이 제안 수락이 되지 않는지 검사합니다.
- 수락·거절·Escape·500ms 보호·늦은 응답 폐기·새 세션·네 설정 개별 적용을 검사합니다.
- `pnpm test` 110개와 TypeScript·Vite 빌드를 통과했습니다.
- 지원·주문 브라우저 검사 84개 항목을 실행했습니다. 최초 실행에서 작은 창의 큰 글씨 주문 버튼과 사진 한 줄로 바뀐 알림 검사가 실패해 보완했고, 해당 주문 조합·알림 검사 14개를 재실행해 모두 통과했습니다. 나머지 항목은 최초 실행에서 통과했습니다.

브라우저 검사는 `backendSupport.browser.test.mjs`, `support.browser.test.mjs`, `order.browser.test.mjs`를 사용합니다. 실제 API 개발 서버·개발 샘플·배포 미리보기 주소를 각각 `ORDER_BROWSER_URL`, `ORDER_SAMPLE_BROWSER_URL`, `ORDER_PRODUCTION_URL`에 지정하고 외부 Playwright 모듈을 제공합니다. 서비스 의존성은 추가하지 않습니다.

개발 샘플 서버의 `/?support=large_text`에서 직접 확인할 수 있습니다.
