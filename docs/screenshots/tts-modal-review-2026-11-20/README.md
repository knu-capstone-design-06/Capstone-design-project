# 화면 도움·장바구니 창의 음성 안내 보류 검증

2026-11-20, PR #79의 `fb192f2` 이후 리뷰 수정을 확인했습니다. 화면 도움·장바구니 창이 열리면 읽던 안내를 중단하고, 창 뒤로 도착한 응답도 자동으로 읽거나 마이크를 다시 열지 않습니다. 닫은 뒤에는 사용자가 [다시 말하기] 또는 [마지막 안내 다시 듣기]를 선택합니다. 옵션 창과 같은 동작입니다.

안내를 읽는 상태 줄에는 스피커 아이콘을 사용하고, 대답 버튼이 없는 상태에는 빈 버튼 영역을 만들지 않습니다. 모달 보류는 창을 여는 효과보다 먼저 하나의 효과에서 적용해 창별 상태가 서로 덮어쓰지 않게 했습니다.

## 환경과 범위

- Windows 개발 PC, Node.js 24.21.0, pnpm 11.25.0, Edge headless, 1080×1920, 기기 배율 1.
- API 모드와 별도 개발 샘플 서버에서 기존 브라우저 검사를 실행했습니다. 인식·음성 합성과 HTTP 응답은 모의 객체 또는 고정 응답입니다.
- 아래 PNG는 배포 빌드의 Vite preview에서 같은 고정 응답을 사용해 캡처했습니다. 개발 전용 로그 버튼이 없는 화면이며 이미지 후처리는 하지 않았습니다.
- 실제 마이크·스피커·외부 AI·DB·G10 또는 Windows 배율·브라우저 F11 조건을 이번에 다시 검증하지 않았습니다. [기존 화면의 실제 음성·DB 검증](../../DB-Voice-Order-Integration-Verification-2026-11-16.md)과 구분합니다.

## 검사 결과

| 검사 | 결과 |
|---|---|
| 새 모달 회귀 6개를 수정 전 실행 | 6개 모두 읽기 중단 또는 늦은 응답 차단에서 실패해 재현 |
| 같은 회귀 6개를 수정 후 실행 | 모두 통과. 두 창의 읽는 중·처리 중, 기본·큰 글씨·큰 버튼·낮은 화면 조합 포함 |
| `pnpm test` | 단위 158개 통과 |
| `node --test src/features/order/voiceWait.integration.test.mjs` | TTS·터치 대기 연동 6개 통과 |
| `pnpm build` | TypeScript 검사·Vite 빌드 통과 |
| 음성·접근성 브라우저 파일 전체 | 41개 통과, 생략 없음. 새 모달 회귀 6개 포함 |
| 배포 빌드의 대표 모달 회귀 | 기본 화면 도움·큰 글씨/큰 버튼/낮은 화면 장바구니 2개 통과. 위 41개와 별도 실행 |

모달 검사는 열려 있는 동안과 닫은 뒤 각각 자동 재청취 지연 400ms보다 긴 600ms를 기다려 읽기·마이크 자동 재개가 없는지 확인합니다. 수동 다시 듣기는 같은 안내를 재생하고 새 음성 POST를 만들지 않는 것도 확인했습니다. 기존 옵션 창 검사는 대답 버튼이 없을 때 빈 영역이 없는지도 확인합니다.

저장소 루트에서 실행하는 `voiceWait.integration.test.mjs` 명령은 경로 앞에 `frontend/`를 붙입니다. 같은 checkout의 `voiceController.ts`를 직접 사용하므로 `TTS_VOICE_CONTROLLER_MODULE`은 지정하지 않습니다. 브라우저 검사의 Playwright는 저장소 밖에 설치된 모듈을 기존 `PLAYWRIGHT_MODULE`로 지정했으며 의존성을 추가하지 않았습니다.
