# 메뉴 화면 음성 입력 연결 검증

2026-10-21 Windows Chrome headless에서 1080×1920 세로 뷰포트로 확인했습니다. 기본 화면과 큰 글씨·큰 버튼·낮은 화면을 각각 확인했습니다. `voiceMode.browser.test.mjs`에서 Chrome 음성 인식과 backend 음성 API 응답을 고정 주입했으며, 실제 마이크 권한·발화 인식·OpenAI·G10 터치 패널은 검증하지 않았습니다.

| 화면 | 확인한 상태 |
|---|---|
| [메뉴 듣는 중](voice-listening-menu.png) | ON 표시와 부분 인식 문장이 보입니다. 상단 450px 캡처입니다. |
| [확인 질문](voice-question-menu.png) | Chrome이 인식한 문장과 온도 질문, 답변을 듣는 상태와 답변의 부분 인식 문장이 보입니다. 상단 450px 캡처입니다. |
| [메뉴 음성 결과](voice-result-menu.png) | ON 표시, 마지막 인식 문장, 해석 완료 안내, 다시 말하기, 비어 있는 장바구니. 해석 결과를 주문 반영으로 안내하지 않습니다. |
| [낮은 화면·확대·마이크 오류](voice-permission-low-large.png) | 큰 글씨·큰 버튼·낮은 화면에서 권한 오류 안내와 다시 말하기 버튼이 조작 영역 안에 있습니다. |

브라우저 검사 세 개가 통과했습니다. 메뉴 화면에서 `screen_id=menu_list` 요청과 확인 질문 뒤 재인식, 주변 대화 뒤 확인 질문 유지와 짧은 답변 전송, 주문 확인으로 이동할 때 마이크 종료, 권한 오류·확대 화면 배치를 확인했습니다. 실제 장비에서는 Windows·브라우저 배율 100%, F11 전체 화면에서 마이크 권한과 소음 환경을 따로 확인해야 합니다.
