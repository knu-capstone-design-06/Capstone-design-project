# [처음으로] 확인 창과 대답 줄의 정렬

- 날짜: 2026-11-26
- 대상: PR #87 `feat/frontend_support`
- 촬영: Windows Microsoft Edge headless, 1080 × 1920 CSS px, device scale factor 1, 브라우저 확대율 100%.
- 범위: 개발 서버와 고정 HTTP 응답을 사용한 프론트 검증입니다. 실제 backend와 G10의 F11 장비 검증은 포함하지 않습니다. 그림의 [터치 로그 보기]는 개발 서버에만 보이는 버튼입니다.

## 바뀐 것

- [처음으로] 확인 창: 폭 900px(x 90–990)의 창 왼쪽에 글자 폭의 대답 둘이 모여 있던 것을, 내용 열(x 48–1032)에 선 창과 같은 너비의 두 대답(x 80–531, 549–1000, 높이 88px)으로 수정했습니다. 큰 글씨 설정에서는 대답이 한 줄에 하나씩 창의 폭을 다 쓰고, 낮은 화면에서는 아래 조작 영역의 위 끝에서부터 섭니다.
- 확인 창의 안내: “'처음부터 주문하기'를 누르면 담은 메뉴 N개(금액)가 모두 지워져요.”를 보이고, 담은 메뉴가 없으면 “'처음부터 주문하기'를 누르면 처음 화면으로 돌아가요.”를 보입니다. 고객이 화면 도움에서 고른 설정이 켜져 있을 때만 “화면 도움에서 고른 설정은 그대로예요.”가 함께 보입니다. 두 대답은 창이 뜬 뒤 500ms 동안 누름을 받지 않습니다.
- 오류 안내의 대답 줄: 글자 폭의 버튼이 왼쪽에 모여 있던 것을, 카드 폭을 대답 수만큼 같은 너비로 나누도록 수정했습니다.
- 장바구니 창의 아래 줄: [닫기]·[주문 확인]이 하단 주문 바의 [처음으로]·[주문 확인]보다 11.5px 위에 서던 것을 같은 높이로 맞췄습니다.

## 검증

- 화면·창·안내·오류 안내 51종을 표시 설정 9가지(기본, 큰 글씨, 큰 버튼, 큰 글씨 + 큰 버튼, 낮은 화면, 고대비, 간편 화면, 단계별 안내, 큰 글씨 + 낮은 화면)로 수정 전후에 찍어 422개 화면을 픽셀 단위로 비교했습니다. 개발 서버에만 있는 버튼 자리를 가리고 보면 234개는 한 픽셀도 달라지지 않았습니다. 달라진 188개 가운데 179개는 위의 수정과 그에 따른 자리 이동, 개발용 타일이 main과 같은 자리로 돌아간 것, 캡처마다 조금씩 달라지는 상품 그림(같은 상태를 두 번 찍었을 때 1~79픽셀)이었습니다. 나머지 9개는 큰 글씨 설정 + 낮은 화면에서 상품을 누른 뒤 목록의 스크롤 위치가 달랐던 화면입니다. 누르기 전의 화면은 같았고, 원인은 확인하지 못했습니다.
- 이 비교 뒤에 확인 창의 설정 안내 줄과 낮은 화면에서의 자리를 한 번 더 수정했고, 확인 창 화면은 다시 찍어 확인했습니다.
- 확인 창의 대답은 9가지 설정 모두에서 하단 주문 바의 [처음으로]와 겹치지 않았습니다(1080 × 1920). 창 높이가 더 낮으면 겹칠 수 있어(1080 × 600 이하의 기본 글자 크기, 1080 × 650–800의 큰 글씨 설정) 500ms의 누름 보호를 두었습니다.
- `support.browser.test.mjs`의 두 검사가 안내 문구, 창과 대답의 좌우 끝·간격·높이, [처음으로]와의 겹침, 창이 뜬 직후와 연달아 누른 입력을 확인합니다.
