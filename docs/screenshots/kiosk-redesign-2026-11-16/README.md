# PR #70 주문 화면 개편 검증 (2026-11-16)

프론트 담당자 요청으로 PR #87 `c5df1fe`의 컴포넌트와 화면 배치를 PR #70에 가져와 검증했습니다. 원본 컴포넌트의 기능별 커밋은 출처를 기록해 가져왔고, 실제 전달 없는 직원 호출 표시·모의 주문 안내·원래 주문번호·높이 복귀와 스크롤 기록을 별도 커밋으로 보완했습니다. 현재 브랜치에는 main `582be78`이 들어 있습니다.

## 촬영 조건

- Windows 개발 PC, Node.js 24.21.0, Microsoft Edge headless.
- 뷰포트 1080 × 1920 CSS px, device scale factor 1, 브라우저 확대 100%에 해당하는 조건입니다. 실제 G10의 Windows 배율·F11 검증을 대신하지 않습니다.
- `VITE_ORDER_SAMPLE=true` 개발 서버의 17개 상품·메모리 장바구니를 사용했습니다. 실제 결제·매장 전달·실제 backend는 실행하지 않았습니다.
- 메뉴·옵션·장바구니·주문 확인·완료는 아메리카노 1개와 샌드위치 1개를 담은 예시입니다. 확대·낮은 화면 예시는 빈 장바구니에서 촬영했습니다.
- 음성 이미지는 모의 인식기로 만든 듣는 상태입니다. 실제 마이크나 음성 해석 결과가 아닙니다. 지원 제안도 개발용 시험 장치로 띄웠으며 실제 판단 응답과 연결하지 않았습니다.
- 동작 줄이기 설정과 애니메이션 정지 옵션을 사용했습니다. 정지 이미지로 움직임이나 깜박임을 평가하지 않습니다.
- 개발 모드여서 터치 로그 확인 버튼이 보입니다. 개인정보·실험 참가자·실제 고객 주문은 없습니다.

## 실행 검증

- 단위 테스트 107개 통과, TypeScript 검사와 Vite 배포 빌드 통과.
- 주문·터치·음성·접근성·지원 제안·기존 #70 피드백의 브라우저 검사 여섯 파일을 실행했습니다. 개발 샘플과 프로덕션 주소를 모두 지정했으며 건너뛴 검사는 없습니다.
- 전체 124개 중 처음에는 122개 통과·2개 실패였습니다. 기존 #70에서 합쳐진 터치 테스트가 옛 내부 `main` 스크롤을 전제로 하고 있었습니다. 새 기본 화면의 실제 문서 스크롤로 준비하도록 고친 뒤 터치·피드백 검사 43개를 모두 재실행해 통과했습니다. 나머지 검사 결과와 합쳐 최종 124개 항목이 통과한 상태입니다.
- 원시 기록의 세션 경계·포인터 취소·모달 뒤 후보 제외·하단 바 가림·개발 창, 낮은 화면의 복귀 누름 시작/종료·이름 있는 창 스크롤·설정 유지를 확인했습니다.
- 확인 질문·짧은 대답·실패 뒤 재발화는 현재 완료 문구에 맞춰 통과했습니다. 이번 화면은 #79의 자동 TTS를 포함하지 않습니다.
- 모의 주문 안내, 개발 샘플 번호 접두사 유지, 직원 호출 버튼과 완료 안내의 미표시를 확인했습니다.

재현 명령은 [주문 기능 README](../../../../frontend/src/features/order/README.md#확인-절차)를 따릅니다. 브라우저 검사에는 외부 Playwright가 필요하며 서비스 의존성은 추가하지 않았습니다.

## 남은 작업

- 실제 G10에서 1080 × 1920·Windows/브라우저 배율 100%·F11과 터치 도달·스크롤·한국어 음성·마이크·스피커를 확인해야 합니다.
- #72 → #79 → #70 순서로 통합하는 안을 유지합니다. 앞 PR이 병합된 main을 받아 `OrderPage.tsx`, 음성 표시·검사와 README 충돌을 해결하고 다시 검증해야 합니다. #72의 특징 전송·`data-log-scroll`, #79의 모달 진입 시 읽기 중단·재청취 동작을 새 창에 맞춰야 합니다.
- 개발용 지원 카드의 상품 가림 후보와 `largeView` 관측 기록은 자동 지원·터치 비교 실험에 연결하기 전 후속 작업입니다. 서버 프리셋·반응·관측 구간 계약은 이번 PR에서 바꾸지 않았습니다.
- 새로운 직원 호출·실제 결제·매장 전달은 구현하지 않았습니다. 모의 주문이 현재 범위입니다.
