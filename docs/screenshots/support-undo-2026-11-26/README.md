# 서버 제안을 수락한 뒤의 적용 알림과 [원래대로]

- 날짜: 2026-11-26
- 대상: PR #87 `feat/frontend_support`
- 촬영: Windows Microsoft Edge headless, 1080 × 1920 CSS px, device scale factor 1, 브라우저 확대율 100%.
- 범위: 개발 서버에서 `window.kioskSupportDraft.receive()`로 넣은 고정 응답을 사용한 프론트 검증입니다. 실제 backend의 제안과 G10의 F11 장비 검증은 포함하지 않습니다. 그림의 [터치 로그 보기]는 개발 서버에만 보이는 버튼입니다.

## 표시와 동작

- [적용하기]를 누르면 제안한 설정이 켜지고, 상품 목록 위의 알림 자리에 적용 알림이 잠깐 뜹니다(다음 터치나 2,750ms 뒤에 닫힘). 문구는 제안의 질문과 같은 말입니다: “글씨를 크게 바꿨어요.”, “버튼을 크게 바꿨어요.”, “간편한 화면으로 바꿨어요.”, “주문 순서 안내를 켰어요.”
- 키오스크가 켠 설정이 남아 있는 동안 [화면 도움] 옆에 [원래대로]가 섭니다(개발용 일괄 확대 시안의 [원래대로]와 같은 자리·같은 모습).
- [원래대로]를 누르면 키오스크가 켠 설정이 모두 꺼지고 “바꾸기 전 화면으로 돌아갔어요.”가 뜹니다. 고객이 화면 도움에서 직접 켠 설정은 그대로입니다. 처리 중·오류 안내가 떠 있을 때와 주문 완료 화면에서는 알림 없이 끄기만 합니다.
- 키오스크가 켠 설정을 고객이 화면 도움에서 모두 직접 끄거나 다시 켜면 [원래대로]는 사라집니다. 같은 세션에서 이미 답한 제안은 되돌린 뒤에도 다시 뜨지 않습니다.
- [처음으로]로 새로 시작하거나 주문을 마치면 키오스크가 켠 설정이 끝나는 것은 전과 같습니다.

## 검증

`support.browser.test.mjs`의 검사가 앱의 시간을 멈춘 채 적용 알림의 문구, [원래대로]의 자리(높이와 간격), 알림을 띄운 누름이 그 알림을 닫지 않고 그 뒤의 터치와 2,750ms가 닫는지, 제안 둘을 받아들인 뒤 [원래대로] 한 번에 키오스크가 켠 설정이 모두 꺼지고 고객이 켠 설정은 남는지, 답한 제안이 다시 뜨지 않는지, 화면 도움에서 직접 끈 뒤 [원래대로]가 사라지는지를 확인합니다.
