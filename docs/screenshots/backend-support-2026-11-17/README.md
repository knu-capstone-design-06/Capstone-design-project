# 서버 UI 변경 제안 확인 (2026-11-17)

기본 API 모드에서 `/features`를 실제로 호출하고 고정 HTTP 응답을 반환해 촬영했습니다. 1080×1920 세로, device scale factor 1, Windows 개발 PC의 Edge headless 조건입니다. 원본 영상·실험 참가자 데이터는 사용하지 않았습니다.

| 이미지 | 상태 |
|---|---|
| [확인 팝업](backend-support-confirm.png) | 서버의 `large_text` 제안. 아직 설정을 적용하지 않았으며 유지·적용을 선택할 수 있음 |
| [큰 글씨 적용](backend-support-large-text.png) | 수락 후 기존 200% 큰 글씨만 적용. 큰 버튼은 별도 설정으로 유지 |
| [낮은 화면·큰 글씨·큰 버튼](backend-support-low-large.png) | 기존 접근성 설정을 유지하면서 `step_guide` 확인창과 두 대답을 하단 조작 영역 안에 표시 |

2026-11-18에는 [개발용 큰 버튼 확인창](draft-large-button-confirm.png)을 같은 해상도·배율의 Windows Edge에서 추가로 촬영했습니다. 개발 샘플에서 `?support=large_button&confirm=0`으로 열었으며, 확인창이 뜰 때까지 설정은 그대로였습니다. [적용하기]를 누르자 큰 버튼만 켜졌고 서버 요청은 없었습니다.

프론트 담당자는 현재 파일럿 기준을 기본 전송에 사용하도록 요청했습니다. 최근 2초의 횟수, 반복 800ms·24 CSS px, 현재 화면 방문의 전경 체류 누적 시간을 사용하며 미관측·미산출 구간은 보내지 않습니다. 원시 기록이나 확장 `interaction`은 전송하지 않습니다.

검증은 네 가지 설정의 독립 수락, 거절·Escape, 중복 억제, 잘못된 응답·다른 세션·AI 불가 무시, 다른 창 조작과 페이지 숨김 뒤의 늦은 응답 폐기, 새 이용의 자동 설정 초기화, 네트워크·410 처리, 개발 샘플 전송 제외, 배포 화면 연결을 포함합니다. 단위 검사 111개와 TypeScript·Vite 빌드가 통과했습니다. Edge 브라우저 신규 연결 검사 13개와 기존 회귀 항목 124개(최초 122개 및 주소를 지정해 별도 확인한 배포 검사 2개), 합계 137개를 확인했습니다. 신규 연결 검사는 건너뜀 없이 13개가 통과했고 기존 회귀 항목에도 남은 실패·미확인 항목은 없습니다.

현재 main의 backend는 `support.preset: none`만 반환합니다. 이 기록은 실제 AI가 지원을 판단한 결과나 G10 실기기 통합 결과를 뜻하지 않습니다. 실제 장비의 Windows·브라우저 배율 100%·F11 전체 화면에서 터치 도달·시각 배치를 최종 확인해야 합니다.
