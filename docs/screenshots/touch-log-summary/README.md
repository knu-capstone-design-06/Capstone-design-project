# 개발용 원시 터치 로그 요약

2026-10-17 프론트 담당자가 선택한 로컬 원시 로그 요약 범위입니다. 기존 ‘터치 로그 보기’ 창에서 보관 중인 현재 세션의 기록 수와 대상 밖 비율, 화면 방문별 표를 확인합니다. 서버용 통계나 실패·반복·체류시간 판정은 포함하지 않습니다.

Windows Chrome headless, 기기 배율 1·브라우저 확대율 100%에서 고정 주문 API 응답으로 촬영했습니다. 외부 웹폰트 요청은 차단해 시스템 대체 글꼴을 사용했습니다. 키오스크 주문 화면의 접근성 설정과 함께 개발 확인 창의 화면 내 배치·가로 넘침·스크롤 접근을 검증한 자료입니다. 개발 확인 창 자체는 고정 크기의 개발 도구입니다.

단위 테스트는 현재 세션 분리, 활성·비활성 대상·영역 밖 입력, 누락 정보와 비율의 `null`, 종료·취소·중단 기록, 같은 화면 재방문, 버퍼 제한을 확인합니다. 원시 기록의 수를 세므로 지워진 시작 기록과 종료 기록을 임의로 연결하거나 성공·실패로 판단하지 않습니다. 입력이 없거나 대상 정보가 부족하면 비율을 0%로 채우지 않습니다.

화면 검사는 1080×1920·1920×1080·1365×768·390×844 × 기본/큰 글씨+큰 버튼 × 기본 높이/낮은 화면의 16개 조합에서 요약 창과 방문별 표·최근 기록의 접근을 확인합니다. 기존 수집·세션 분리·버퍼 제한·표시 일시정지·JSON 내보내기·하단 주문 바 가림 검사도 함께 실행합니다. 실제 G10의 터치 패널·물리적 도달 범위·F11 전체 화면과 실제 스크린리더 출력은 별도 확인이 필요합니다.

검증 결과: Windows Node.js 24.21.0에서 `npm test` 62개, WSL Node.js 24.15.0에서 `npm run build`(TypeScript·Vite), Windows Chrome headless에서 터치 로그 브라우저 검사 34개가 통과했습니다. 운영 미리보기 URL을 지정한 개발 확인 창 검사도 별도로 1개 통과했으며 운영 빌드에서 개발 도구가 표시되지 않음을 확인했습니다. `git diff --check`도 통과했습니다.

실행 방법은 [주문 기능 README](../../../frontend/src/features/order/README.md#개발용-원시-터치-로그-요약)를 참고합니다. 기존 브라우저 검사 실행 시 `TOUCH_LOG_SUMMARY_SCREENSHOT_DIR`를 지정하면 위 대표 이미지 세 개를 저장할 수 있습니다.
