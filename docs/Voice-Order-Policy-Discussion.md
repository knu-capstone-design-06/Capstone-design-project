# 음성 주문 남은 정책: 팀 합의 검토안

작성 기준: 2026-11-09, PR #82가 병합된 `main`의 계약·백엔드 코드와 열린 PR #67. 이 문서는 **결정안이 아닌 검토용 제안**이다. 팀원이 승인하기 전까지 계약이나 설정을 바꾸지 않는다.

## 현재 확인된 사항

- `VOICE_EXECUTE_TOOLS` 기본값은 꺼져 있다. 이를 켠 경우 `completed` 결과의 도구를 백엔드 주문 서비스로 순서대로 실행하고, 모두 성공하면 `actions: [cart_updated]`를 반환한다. 하나라도 실패하면 묶음을 되돌린다. 도구 입력마다 Cart 버전이 올라간다.
- `needs_confirmation`은 즉시 실행하지 않는다. 현행 계약은 저장된 제안에 대한 음성 답변을 사용하며 버튼 수락 API는 없다. PR #67은 장바구니 맥락과 확인·경합 안전장치를 보완하는 미병합 PR이다.
- 동일 음성 요청의 같은 멱등성 키·본문은 기존 접수를 재생한다. 음성 기록은 프로세스 메모리에 있으며 재시작 시 사라진다. 최근 10턴과 1시간은 제안값이고, 현재 만료 정리는 다음 음성 요청 접수 시 실행되므로 정확히 1시간 뒤 삭제를 보장하지 않는다.
- 11월 8일 개발 PC의 격리 메모리 환경에서 실제 마이크·프론트·백엔드·OpenAI를 거쳐 모의 주문번호가 표시됐다고 사용자 확인을 받았다. 같은 환경에서 온도 누락·없는 상품·수량 초과·유효 상품과 없는 상품 혼합 사례 각각 1회 장바구니가 변경되지 않았다. 모델의 모든 발화나 실장비 성능을 보장하는 결과는 아니다.

## 결정 1. 실행 기본값과 장바구니 버전

**현재:** 실행을 켰을 때 도구마다 버전이 오르고, 모든 도구 성공 후 `cart_updated`로 프론트에 재조회를 요청한다. PR #67은 장바구니가 해석 후 바뀌는 경우의 재확인도 제안한다.

**제안:** 첫 시연에서는 현재의 도구당 버전 증가와 묶음 전체 성공·실패 방식을 유지한다. 프론트는 버전 차이를 변경 횟수로 해석하지 않고 `cart_updated`를 받으면 서버 Cart를 다시 조회한다. 기본 활성화 여부는 PR #67 최종 검토와 프론트 재조회·동시 조작 검증 이후 별도로 결정한다.

- 대안: 음성 요청 한 건당 버전 1회 증가. 장바구니 동시성·DB 트랜잭션·터치 충돌·멱등성·프론트 기대값의 계약 및 구현 변경 범위를 먼저 확인해야 한다.
- 예시: Cart v5에서 유효한 도구 두 개가 모두 성공하면 현행은 v7이다. 중간 실패는 전체 롤백되어야 한다.
- 확인 담당: 백엔드·프론트·AI. 결정할 것: 증가 단위, 프론트 재조회 조건, 기본 활성화의 선행 검증.

## 결정 2. 확인 질문에 버튼 추가 여부

**현재:** 확인은 다음 음성 발화 경로이며 버튼 전용 수락 API는 없다.

**제안:** 첫 시연에서는 현재 음성 확인과 터치 주문 대안을 유지하고, 확인·취소 버튼은 후속 단계로 둔다. 버튼을 도입하기로 하면 제안 식별·유효기간·일회 소비, 버튼과 음성의 동시 수락 방지, Cart 변경 시 재확인, 취소·만료·오류 응답을 먼저 계약으로 정한다.

- 대안: 첫 시연부터 버튼을 지원한다. 프론트 화면, 음성 계약, 백엔드 제안 저장과 멱등성 검사가 함께 필요하다.
- 확인 담당: 프론트·AI·백엔드. 결정할 것: 시연에 버튼이 필요한지, 음성 실패 시 이용자가 어떻게 터치 주문을 계속하는지.

## 결정 3. 음성 기록과 삭제

**현재:** 백엔드 음성 요청·대화 맥락은 메모리 보관이며 DB 영속 저장은 하지 않는다. 제안값은 최근 10턴·1시간이며, 정리는 다음 요청 접수 시 일어난다. 주문 완료가 음성 기록을 즉시 삭제한다는 보장은 없다.

**제안:** 첫 시연은 메모리 보관을 유지한다. 녹음 원본과 인식 문장을 별도로 DB에 저장하지 않는 범위를 지키고, 음성 텍스트의 외부 OpenAI 전송과 서버 임시 보관을 참가자에게 안내할지 팀에서 확정한다. 세션 종료 시 즉시 삭제 및 보장 가능한 만료 방식은 보관·재전송 정책과 함께 후속 계약·구현에서 정한다.

- 대안: 완료 또는 명시적 종료 시 즉시 삭제. 기존 요청의 상태 조회·같은 키 재전송 보장과 충돌할 수 있으므로 구분할 기록과 삭제 시점을 정해야 한다.
- 확인 담당: 백엔드·AI·실험 담당. 결정할 것: 안내 문구, 삭제 기준과 시점, 재전송 기록 예외.

## 결정 4. 화면 식별자

**현재:** 음성 메뉴 요청은 `menu_list`를 사용하며, 터치 로그에서는 `menu`를 사용한다. 양측이 같은 값이어야 하는지와 매핑 소유자는 미정이다.

**제안:** 첫 시연은 현행 값을 유지하고 서버에서 임의로 변경하지 않는다. 담당자끼리 공통 ID 또는 명시적 매핑을 선택하고, 확정 후 contract·프론트·백엔드·분석 예시를 함께 맞춘다.

- 확인 담당: 프론트·백엔드·AI·비전. 결정할 것: 공통 표와 각 화면 값, 음성 요청과 터치 기록을 연결할 방법.

## 검토 요청 문구
