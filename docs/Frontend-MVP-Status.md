# 프론트엔드 MVP 작업 현황

- 확인일: 2026-11-20
- 구현 기준: main `9317b0b`(PR #70·#71·#72 병합). PR #79·#87의 미병합 작업은 별도로 표시합니다.
- 범위: 프론트의 주문·접근성·터치 관측·음성·지원 제안과 검증 현황입니다. 다른 담당 영역의 전체 상태나 팀 계약의 최종 확정을 판정하지 않습니다.
- 기준 문서: [프론트 README](../frontend/README.md), [주문 기능 상세](../frontend/src/features/order/README.md), [터치 로그 검토](Touch-Log-Review.md), [세션·이벤트·음성 정책 제안](Session-Event-Voice-Policy-Proposal.md).

## main에 반영된 기능

| 영역 | 프론트 구현 범위 | 검증·제한 |
| --- | --- | --- |
| 상품·장바구니·모의 주문 | 상품 그림·분류·쪽 넘김, 옵션·수량 선택, Cart 추가·변경·삭제, 장바구니 전체 보기, 주문 확인·완료·서버 주문번호 표시. 기본 API 모드는 backend 응답 사용 | 실제 backend의 주요 터치 주문·응답 유실 재확인은 2026-10-14 Docker에서 검증. 실제 결제·재고 차감은 미연결 |
| 주문 오류·연속 입력 | 요청 중 변경 차단, 버전 충돌 처리, 같은 키·본문의 수동 재확인, 불완전한 응답 검사. 창 닫기·화면 전환 후 하단 바와 삭제 후 되돌리기에는 500ms 보호 적용 | 보호 중 무시한 입력이 더 오면 그때부터 다시 대기. 실제 장비의 연속 입력·장애 검증은 별도 |
| 수동 접근성·화면 높이 | 큰 글씨(200%)·큰 버튼·간편 화면·단계별 안내·낮은 화면·고대비를 화면 도움 창에서 전환. 낮은 화면은 위쪽 [화면 위로 올리기]로 해제 | 기준 1080×1920, Windows·브라우저 배율 100%. 실제 G10의 F11·터치 도달 범위 확인 필요. 높은 화면은 제외 |
| 설정·새 이용 | 수동 설정은 로컬에 저장하고 [기본 화면으로]에서 초기화. 새 주문·새로고침은 새 서버 세션·빈 Cart로 시작하며 서버 제안으로 켠 설정은 해제 | 다음 이용자의 수동 설정 초기화 정책은 팀 합의와 구분 |
| 음성 입력·Cart 재조회 | [말로 주문하기] 마이크 버튼에서 Chrome 인식·backend 요청·상태 조회·문장/질문/결과/오류 표시. `actions: [cart_updated]` 후 같은 세션 Cart 재조회. 터치 저장 중 결과는 보류 후 처리 | `completed`나 `tool_calls`만으로 주문 변경을 확정하지 않음. 실제 마이크·외부 AI·G10 확인은 별도 |
| 수동 화면 읽기·누름 소리 | 사용자가 켜고 끄며, 마이크와 수동 읽기의 동시 사용 조정 | 자동 음성 응답 읽기와 구분. 실제 한국어 음성·스피커 검증 필요 |
| 로컬 터치 기록 | 포인터·화면 방문·설정·주문/선택/음성 상태 기록, 개발 창의 요약·JSON 내보내기 | 보관 중인 현재 세션의 기록. 불편·실패를 판정하지 않으며 원시 기록은 업로드하지 않음 |
| 특징 전송 | API 모드에서 연속한 약 2초 구간의 통계 5개를 단일 `/features` 전송기로 전송. `VITE_TOUCH_INTERACTION_DRAFT=true`인 공동 파일럿에서만 같은 요청에 `touch.interaction` 추가 | 관측 불충분 구간·숨김·종료·개발 샘플에서는 전송하지 않음. 확장 필드가 backend를 지나 AI에 전달됐는지는 HTTP 성공만으로 확인할 수 없음 |
| 지원 제안·수락 후 적용 | 큰 글씨·큰 버튼·간편 화면·단계별 안내를 하단 전용 공간의 비모달 안내 바로 제안. 제안 중 다른 조작 가능. 수락한 항목만 적용하고 중복·이전 화면/방문의 늦은 응답을 무시 | 현재 서버는 `preset: none`만 반환하므로 실제 AI 제안 생성은 미검증. 수락·거절·해제는 프론트 상태이며 서버 이벤트 전송은 미연결 |
| 개발 샘플 | `VITE_ORDER_SAMPLE=true` 개발 서버에서 17개 상품·모의 주문·음성 인식 테스트 제공 | backend 주문·음성·특징 API를 호출하지 않음. 프로덕션에서는 샘플 설정을 무시하고 서버 오류를 샘플로 대체하지 않음 |

기본 전송의 반복 800ms·24 CSS px, 현재 방문의 전경 누적 `dwell_ms`는 프론트 담당자가 선택한 파일럿 기준입니다. 관측 불충분을 `null`로 구분하며 팀 전체 계약이나 불편 판단 기준으로 확정하지 않습니다. 현재 상세 전송 정책과 범위는 [서버 제안 연결 기록](../frontend/src/features/order/README.md#서버-ui-변경-제안-연결-2026-11-17)과 [터치 로그 검토](Touch-Log-Review.md)를 따릅니다.

## MVP까지 남은 프론트 과업

순서는 의존 관계에 따른 작업 제안입니다. MVP 필수 지원과 미정 인터페이스는 팀이 결정합니다.

| 과업 | 프론트에서 할 일 | 선행 조건·완료 확인 |
| --- | --- | --- |
| 기본·확장 특징의 실제 전달 확인 | 구현된 단일 전송기의 실패·재개·구간 경계를 실제 서비스와 확인하고 선택적 확장의 소비 여부 검증 | 필드·단위·결측·관측 구간의 팀 합의와 `contract/` 반영. HTTP 200을 확장 전달 성공으로 해석하지 않음 |
| 비전 관측 결합 | 제공받은 관측값을 터치와 같은 구간에 맞춰 backend에 전달 | 실행 위치·전달 방식·시각·결측·오류 표현 합의. 프론트는 backend와만 통신 |
| 실제 AI 지원·반응 전송 | 구현된 제안 바를 실제 판단 결과와 연결하고 수락·거절·적용·해제·실패를 구분해 전달 | 허용 프리셋·결정 ID·이벤트 형식·유효기간·화면/세션 종료 정책 합의. 낮은 화면은 현재 로컬 설정이며 서버 프리셋에 추가하지 않음 |
| 자동 TTS 병합·정책 확인 | #79 최신 커밋 재승인 후 병합하고 #87 등 후속 화면과 재검증 | #92와 함께 들어오기 전 실패·무시 응답의 기존 질문/대답 대기 정책을 맞추는 기존 리뷰 항목 확인. 실제 음성 서비스·G10 검증 필요 |
| 음성 UI 조작 | 합의된 명령에 따라 글씨·버튼 등 설정 변경과 수락·복귀 처리 | 명령·프리셋·적용 조건·수동 설정 우선순위의 계약 합의 |
| 화면 개편 후속 | #87의 추가 정렬·개발 도구·샘플 주문번호를 검토하고 통합 | PR 작성자들의 병합 순서와 겹치는 파일 조정. 기존 주문·접근성·음성·터치 회귀 확인 |
| 실제 G10·전체 시나리오 | 1080×1920, 배율 100%, F11에서 터치 주문 → 음성 Cart 변경 → 관측 → 제안·수락·복귀 → 모의 주문 완료 및 AI/네트워크 장애 확인 | 실제 장비·연결된 서비스·한국어 음성·마이크·스피커 필요. 고정 응답과 모의 객체 검증과 별도로 결과·스크린샷 기록 |

직원 호출은 실제 전달 경로가 없어 숨깁니다. 실제 결제·재고 차감은 모의 주문 범위에 포함하지 않습니다. 완료 화면 복원·서버 재시작 후 보관·장기 보관·정밀 만료·동적 가격 변경은 후순위입니다.

- [기존 실제 backend 주문 통합](../frontend/README.md#실제-백엔드-주문-통합-검증)은 2026-10-14의 터치 주문과 응답 유실 재확인 범위입니다.
- [PR #70 비모달 안내 바](screenshots/nonmodal-support-2026-11-18/README.md)와 [키오스크 화면 개편](screenshots/kiosk-redesign-2026-11-16/README.md)은 고정 HTTP 응답·개발 샘플의 화면·접근성 검증입니다. 실제 AI가 제안을 골랐다는 증거가 아닙니다.
- [PR #79 통합 검증](https://github.com/knu-capstone-design-06/Capstone-design-project/blob/fb192f2/docs/screenshots/tts-design-integration-2026-11-20/README.md)은 미병합 `fb192f2` 기준입니다. 프론트 단위 158개·TTS/터치 연동 6개·빌드, 실패 수정·실행 설정 보완 후 관련 파일/항목을 재검사한 브라우저 8개 파일 178개 항목을 기록했습니다. 이는 이번 문서 수정에서 재실행한 결과가 아닙니다.
- 같은 #79 검증에서 실제 로컬 FastAPI·Vite 프록시·메모리 주문 저장소·음성 서비스·도구 실행·Cart 재조회를 사용해 기본/확대·낮은 화면의 터치 1개 담기 → 음성 확인 → Cart 2개 반영 → 모의 주문 → 새 세션을 확인했습니다. 인식·합성과 외부 AI 응답은 모의 객체입니다. 실제 마이크·외부 AI·G10 통합과 구분합니다.
- 날짜별 [주문 기능 기록](../frontend/src/features/order/README.md)의 검사 수와 정책은 당시 환경의 결과입니다. 최종 계약 합의·이후 커밋·실제 장비 검증으로 확대 해석하지 않습니다.
- 이번 갱신은 프론트 관련 Markdown 설명만 바꾸며 코드·UI·API·계약은 변경하지 않습니다.
