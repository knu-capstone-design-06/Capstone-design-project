## 현재 구현된 기능

| 영역 | `main`의 구현 범위 | 검증·제한 |
| --- | --- | --- |
| 상품·장바구니·모의 주문 | 상품 분류·옵션·수량 선택, Cart 추가·변경·삭제, 주문 확인·완료·주문번호 표시. 기본 API 모드는 backend 응답을 사용 | 실제 backend의 주요 주문 흐름과 응답 유실 재확인은 2026-10-14 Docker에서 검증. 실제 결제·재고 차감은 미연결 |
| 주문 오류·재시도 | 요청 중 중복 변경 방지, 버전 충돌 처리, 응답 유실 때 같은 키·본문으로 수동 재확인, 불완전한 주문 응답 검사 | 계약의 최종 정책·실기기 장애 검증은 별도 |
| 수동 접근성 | 큰 글씨(200%)·큰 버튼·간편 화면·단계별 안내·낮은 화면·고대비, 기본 화면 복귀 | 로컬 UI 설정이며 자동 지원·서버 프리셋 연동을 뜻하지 않음. 실제 G10 검증 필요 |
| 음성 입력 | 메뉴 화면에서 Chrome 음성 인식, backend 요청·상태 조회, 인식 문장·확인 질문·결과·오류 표시. 무음·유휴 시 음성 모드 자동 종료 안내 | 실제 마이크·OpenAI·G10 연결은 별도 검증 필요 |
| 음성 뒤 Cart 재조회 | backend가 실제 변경 후 `actions: [cart_updated]`를 반환하면 같은 세션의 Cart를 재조회. 터치 저장 중 알림은 보류 후 조회(PR #71) | `completed`나 `tool_calls`만으로 변경됐다고 판단하지 않음. backend 음성 실행 기본값은 꺼져 있고 실제 통합 검증은 남음 |
| 수동 화면 읽기·누름 소리 | 사용자가 화면 읽기와 소리를 켜고 끌 수 있고, 마이크와 화면 읽기의 동시 사용을 조정 | 수동 기능이며 음성 주문 응답 자동 읽기와 다름. 실제 기기의 한국어 음성·스피커 확인 필요 |
| 로컬 터치 기록 | 포인터·화면 방문·설정과 주문/선택/음성 상태를 로컬에 기록. 개발 창에서 현재 세션 요약과 JSON 내보내기 | 최근 2초의 누름·대상 밖·반복 후보·뒤로가기와 현재 방문 전경 체류 시간은 로컬 파일럿. 판단·실패 판정이나 서버 업로드가 아님 |
| 개발 샘플 | `VITE_ORDER_SAMPLE=true` 개발 서버에서 backend 없이 모의 주문과 음성 인식 테스트 | 실제 서버 저장·음성 해석·결제 테스트가 아님. 서버 오류를 샘플로 자동 대체하지 않음 |

로컬 터치 로그의 800ms·24 CSS px 반복 기준과 `dwell_ms` 방문 누적 정의는 파일럿 값이다. 관측 불충분은 `null`로 구분하며 팀 전체의 계약이나 불편 판단 기준으로 확정하지 않는다. 상세 수집 범위와 제한은 [터치 로그 검토](Touch-Log-Review.md)를 따른다.

## MVP까지 남은 프론트 과업

순서는 의존 관계를 보여 주는 **작업 제안**이다. 어떤 지원을 MVP에 반드시 포함할지는 팀이 결정한다.

| 과업 | 프론트에서 할 일 | 선행 조건·완료 확인 |
| --- | --- | --- |
| 1. 터치 특징 전송 | #72 리뷰를 반영하고, 합의된 집계·결측·전송 정책으로 실제 API 모드를 연결한다. 서버에 보내는 구간과 전송 실패를 확인한다 | 프론트·backend·AI·비전이 필드·단위·`null`·관측 구간을 합의하고 `contract/`에 반영. backend가 확장을 보존해 ai-engine에 전달하는 실제 통합 검증 필요 |
| 2. 비전 관측 결합 | 제공받은 비전 관측값을 터치 특징과 같은 관측 구간에 맞춰 backend에 전달한다 | 비전 담당과 실행 위치·전달 방식·시각·결측·오류 표현 합의. 프론트는 backend와만 통신 |
| 3. 자동 지원 제안·적용 | 허용된 지원을 화면에 제안하고, 확인이 필요한 경우 수락 뒤 적용한다. 거절·수동 복귀·되돌리기와 주문 내용 유지를 처리한다 | 비전 판단 층·AI·backend가 결정과 적용 조건을 검증해 제공. 현재 [비전 판단 규칙표 v0](../ai-engine/app/modules/vision/judgment/rule_table_v0.py)은 초안이며 실제 연동·검증은 별도. 프리셋·낮은 화면·기존 수동 설정의 조합 합의 |
| 4. 지원 반응과 오래된 결과 | 제안 수락·거절과 실제 적용·실패·되돌리기를 구분해 전달한다. 이전 세션·이전 화면 방문의 늦은 결과와 중복 결과는 적용하지 않는다 | 결정 ID, 이벤트 주체·형식, 구간 순서·중복·세션 종료 정책 합의. 현재 파일럿 순번만으로 서버 중복 제거를 보장하지 않음 |
| 5. 실제 음성 주문 통합 | 실제 backend 음성 실행과 `cart_updated` 재조회, 확인 질문, 실패·재시도 및 터치 동시 조작을 함께 검증한다 | 백엔드·AI가 음성 실행·확인·버전 정책을 확정하고 실행을 준비. #71의 모의 응답 테스트와 실제 통합 테스트를 구분 |
| 6. 음성 화면 조작·응답 | 합의된 명령에 따라 글씨·버튼·낮은 화면 등 UI 설정을 바꾸고, 필요하면 backend 응답을 자동으로 읽는다 | 음성 명령·프리셋·수락·복귀·TTS 방식 합의. 현재 수동 화면 읽기와 분리해 검증 |
| 7. 화면 개편 정리 | #70의 메뉴 배치·음성 표시 시안을 검토하고 선택된 화면의 조작·접근성·회귀 테스트를 완료한다 | 시안 선택과 PR 범위 확정. 기존 주문·음성·터치 관측과 겹치는 변경을 조정 |
| 8. 실제 G10 최종 검증 | 1080×1920 세로, Windows·브라우저 배율 100%, F11에서 기본·큰 글씨·큰 버튼·낮은 화면, 터치 도달·스크롤·마이크·스피커·한국어 음성을 확인한다 | 실제 기기와 연결된 서비스 필요. 고정 응답·모의 마이크 검증과 별도로 결과와 스크린샷 기록 |
| 9. 전체 시나리오·장애 검증 | 터치 주문 → 음성 Cart 변경 → 관측 → 지원 제안·수락·복귀 → 모의 주문 완료를 확인한다. AI·네트워크 실패 중에도 터치 주문을 확인한다 | 위 계약·실제 연동이 준비된 뒤 프론트·backend·AI·비전과 함께 수행 |

직원 호출은 API·운영 연락처가 없어 현재 구현하지 않았으며 필요 여부와 운영 방식을 정해야 한다. 실제 결제·재고 차감은 현재 모의 주문 범위에 포함하지 않는다. 완료 화면 복원·서버 재시작 후 장기 보관·정밀 만료·동적 가격 변경은 기존 문서의 후순위 항목이다. 높은 화면 모드는 현재 범위에서 제외한다.

## 검증 자료를 읽는 기준

- [실제 backend 주문 통합 기록](../frontend/README.md#실제-백엔드-주문-통합-검증)은 2026-10-14의 터치 주문과 응답 유실 재확인 범위다. 음성 주문·자동 지원 실기기 통합의 증거는 아니다.
- [음성 입력 화면과 PR #71 검증](screenshots/voice-input/README.md)은 고정 응답·모의 음성 인식을 사용한 화면·동시 처리 검사다. 실제 마이크·OpenAI 호출 결과와 구분한다.
- [주문 기능 상세의 파일럿 검증](../frontend/src/features/order/README.md#검증-실행)은 기록된 날짜·환경·설정의 결과다. 이후 작업의 재검증이나 팀 전체 계약 합의를 뜻하지 않는다.
- 코드나 UI는 이번 현황 정리에서 변경하지 않는다. MVP 최종 완료 여부는 실제 G10과 연결된 서비스에서 확인한다.
